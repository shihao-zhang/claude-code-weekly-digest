## Claude Code 产品更新 (Claude Code Updates)

- **[`/design` 进入研究预览：Claude Code 开始产出可编辑 UI，而不是代码 - 2026-08-17]** 本周 Claude Code 最具产品意义的一笔，是把 Claude Design 的 **artboard（画板）工作流搬进了 CLI 与桌面端**：
  - 运行 `/design a few options for {feature}`，Claude **不再直接给你一个代码文件**，而是并排返回若干个**可编辑的 artboard 变体**（构建在 Artifacts 之上）；你挑一个、就地微调，再让 Claude 去实现它
  - artboard 的概念直接对标 Figma——一块「可以对其动手」的工作画布，而不是一张截图
  - 状态明确为 **research preview**，覆盖 Pro / Max / Team / Enterprise 计划；官方与社区都提示命令形态还会变，首个 artboard 仍需对着真实代码库做人工评审再落地
  - 值得注意的是它的方向性：过去一年 Agent 的输出单位一直是 diff，这是第一次官方把**「先出可视化方案、再出实现」**做成 CLI 内的一等流程

  ([explainx 解析](https://www.explainx.ai/blog/claude-code-design-command-artboards-research-preview-2026), [CybersecurityNews](https://cybersecuritynews.com/anthropic-launches-design-skill/), [TestingCatalog](https://x.com/testingcatalog/status/2089499940963643567), [DevelopersIO](https://dev.classmethod.jp/en/articles/20260818-cc-updates-v2-1-234/))

  - 修复 auto mode 在子 Agent 工具里的权限应答处理、异常 Unicode 序列导致的 markdown 渲染变慢、**MCP 诊断打印出已解析的密钥**

- **[Cursor 双线出击：Origin 代码托管 + 事件驱动的云端 Agent - 2026-08-17 / 08-19]** 本周 Tier 2 分量最重的一家，而且两件事都不是小改动：

  **① Cursor Origin（8/17，早期 beta）——直接对着 GitHub 去的代码托管**
  - 面向**全部付费计划（Pro / Teams / Enterprise）默认铺开**，仅企业管理员显式退出者除外——**是 opt-out，不是 opt-in**
  - 首发即带：仓库、pull request（与 GitHub **双向同步**）、代码浏览与搜索、Cursor Agent 接入，以及 Vercel / Depot / Buildkite 集成
  - 落在桌面客户端新的 **Codebase 标签页**中，每个仓库有自己的公开 URL `cursor.com/codebase/[name]`
  - 定位是「为 Agent 而建的代码托管」：不是再做一个 GitHub，而是假设**主要读写方是 Agent 而非人**

  **② 事件驱动的云端 Agent（8/19）**
  - 云端 Agent 可**订阅事件源**——监视 PR、盯一条 Slack 线程、或按 cron 定时触发——有事件时被唤醒
  - **云端 Agent 会自动订阅自己创建的 PR 并把它推到完成**：修 CI、回应 bot 评论
  - 可在**隔离 VM 上拉起子 Agent 并行围攻同一个任务**
  - **可中途给正在工作的 Agent 发消息进行引导而不打断它**——后续消息等到下一次工具调用间隙再插入，而不是当场截断

## 社区热点 (Community Highlights)

- **[GitHub 宕机 7 小时 47 分，而 Cursor Origin 在几小时前刚上线 - 2026-08-17]** 本周社区讨论密度最高的一件事，是一次时间上过于巧合的碰撞：
  - GitHub 于 **8/17 约 13:40 UTC 起中断**，github.com、认证、Actions、API、PR、Issues 与 Copilot 全线受影响，**至约 21:15 UTC 解决，历时 7 小时 47 分**。峰值错误率：网页与 API 约 **20%**，归档下载与 raw 仓库内容约 **50%**
  - 根因是**流量创新高时，Central US 数据中心的一个关键基础设施组件未能同步扩容**，容量压力扩散引发认证失败并波及多个服务。GitHub 已就此发文说明后续工作
  - 而 **Cursor Origin 恰恰在宕机前几小时上线**——需要澄清的是，**Origin 是在宕机之前发布的，不是趁乱补刀**；但这个顺序并不妨碍它成为本周叙事的主角：一家刚被 SpaceX 收购的公司推出面向 Agent 的代码托管，当天 GitHub 就趴了 8 小时
  - 有统计指出这是 GitHub **15 天内的第 7 起事故**——真正让社区不安的不是单次宕机，而是频率

  ([GitHub 官方复盘](https://github.blog/news-insights/company-news/the-august-17-outage-and-the-work-ahead/), [BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/microsoft-confirms-github-is-down-worldwide/), [Forbes](https://www.forbes.com/sites/conormurray/2026/08/17/github-says-it-implemented-a-fix-for-outages/), [VentureBeat](https://venturebeat.com/infrastructure/cursor-launches-origin-code-hosting-platform-as-github-outage-exposes-opening-in-ai-coding-race), [NewsCord：13 家媒体如何framing 这件事](https://newscord.org/article/cursor-launches-origin-code-hosting-platform-for-paid-users-as-github-outage-hit--Story_20260819_CursorcapitalizesonGe357012b))

- **[Origin 的真正争议不是「能不能打 GitHub」，而是「默认开 + 数据条款未公布」]** 社区对 Origin 的批评集中在两点，都和产品能力无关：
  - **默认铺开给所有付费用户**（仅企业管理员可退出），但 **Cursor 至今未公布数据留存条款**——代码托管是所有开发者数据里最敏感的一类，「先默认打开、条款后补」的顺序引发了明确的安全质疑
  - 更结构性的担忧是**垂直整合**：当同一家公司同时控制**编辑器、托管与模型**三层，它的激励会从「借用底座」转向「拥有底座」——而今天让 Origin 看起来可以安全采用的那些属性，恰恰依赖于它还没有拥有底座。叠加 SpaceX 的所有权与 Cursor 每天约 **1.5 亿行代码**的写入量，这条数据流的归属问题被反复提起

## 实用技巧 (Tips & Tricks)

- **用 `ANTHROPIC_DEFAULT_MODEL` 把模型选择从「每次会话手动挑」变成环境属性（Claude Code v2.1.236）**：新增的这个环境变量控制新会话的默认模型。实际价值在于**按环境分档**——本地开发环境设一个便宜模型、CI / 自动化环境设另一个，不再依赖每次记得 `/model`，也不用把模型选择写进每个脚本。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **跨会话消息用 `notify_when_idle` 代替直接打断（Claude Code v2.1.236）**：`SendMessage` 新增该选项，让消息**等对方空闲时再送达**，而不是插进它正在做的事情中间。多会话协作里，「我有个非紧急的东西给你」和「立刻停下看这个」是两种语义，此前只有后者。配合同版 `SendMessage` 对超大消息的前置拒绝，跨会话通信第一次有了基本的流控。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **写 skill 时把 SKILL.md 当索引，而不是把文档全塞进去（Claude Code v2.1.234 的启示）**：官方把 `claude-api` 的上下文开销从 20 万+ token 降到约 2.5 万，靠的是**参考文档按需加载**。如果你在写自己的 skill，这是可直接照搬的结构：主文件只留触发条件与导航，正文拆到 `references/` 下按需读取。官方自己都能不小心让一个内置 skill 吃掉 20 万 token，社区 skill 更值得自查一遍。([The New Stack](https://thenewstack.io/claude-code-token-reduction/))

- **`/export` + `codex exec fork`：把一次探索变成可复用的起点（Codex CLI v0.148.0）**：`/export` 把完整对话导出成 Markdown（剪贴板或文件），`codex exec fork` 从已有会话分叉。组合起来的用法是——**先用一个会话把上下文喂饱（读代码、定位问题），然后 fork 出多个分支去尝试不同方案**，彼此不污染，`/export` 留档做对比。比起「每个方案重开一个会话再解释一遍背景」省下的是最贵的那部分 token。([Release v0.148.0](https://github.com/openai/codex/releases/tag/rust-v0.148.0))

- **hooks 现在能异步跑、还能调 MCP 工具（Codex CLI v0.148.0）**：这条容易被当成小改动。以前 hook 只能是同步的短命令，慢一点就拖住整个回合；现在**可异步执行，并可直接调用 MCP 工具**。意味着「提交前跑一遍完整测试并把结果发到 Slack」这类动作可以挂进 hook 而不阻塞交互——hook 从「小钩子」变成了可编排单元。([Release v0.148.0](https://github.com/openai/codex/releases/tag/rust-v0.148.0))

- **用 `codex agents` 看板管住同时在跑的一堆任务（Codex CLI v0.149.0）**：新增的交互式看板支持搜索、启动、打开、重命名、停止任务，快捷键可配置。并发跑三个以上 Agent 时，**真正的成本不是 token 而是「我现在到底有几个在跑、哪个卡住了」**——这个看板是第一个把该问题正面处理的官方界面。搭配同版 `codex queue` 向已有会话投递消息，本地多任务的编排闭环基本齐了。([Release v0.149.0](https://github.com/openai/codex/releases/tag/rust-v0.149.0))

- **注意 `/resume` 的四个历史坑本周才修完（Claude Code v2.1.239）**：如果你之前觉得 `/resume` 「有点不准」，不是错觉——本版一次修了：跨目录挑到同名会话、**文件只是被 touch 就显示为最近变更**、all-projects 模式下推荐已删除的目录、自定义会话标题在对话超约 64 KB 后消失。长期靠 `/resume` 接续工作的人，值得升级后重新建立对它的信任。([Release v2.1.239](https://github.com/anthropics/claude-code/releases/tag/v2.1.239))

## 横向洞察 (Cross-cutting Insights)

**这一周，各家不约而同地在解决同一个问题：会话不再是一次性的。** 把本周的更新按功能而非厂商重排，会看到一条异常整齐的线。Codex 给了 `/export`（导出）、`codex exec fork`（分叉）、会话归档 / 恢复、`codex queue`（向已存在的会话投递消息）、以及一个管理并发任务的 `codex agents` 看板；Claude Code 给了 `notify_when_idle`（等对方空闲再送达）、`/goal` 的退避式 check-in、Windows 上的跨会话消息、以及一次性修完 `/resume` 的四类误判；Cursor 让云端 Agent **订阅事件源**并在被唤醒时继续推进，还允许你**中途给正在工作的 Agent 发消息而不打断它**；Kiro 加了流空闲看门狗与 60 分钟流式超时；OpenCode 让失败的子 Agent 带上**可恢复的 `task_id`** 返回。而 MCP 在 8/22 的新路线图里把「长时循环、流式结果、工作中途引导」列为第一优先级，官方原话是「现代 Agent 工作负载已经不再适配标准的请求-响应模式」。**当产品层和协议层在同一周说同一句话时，那通常不是巧合，是一个抽象终于稳定下来了。** 过去两年 Agent 的心智模型是「一问一答，答完即弃」；这一周所有人都在承认，它其实是**一个需要被寻址、被暂停、被恢复、被并发管理的长生命周期进程**——这已经是操作系统的问题域，不是聊天框的问题域。

**与此同时，竞争的战场明显从「Agent 好不好用」上移到了「Agent 跑在谁的地基上」。** Cursor 本周做的两件事必须合起来看：8/17 推出 Origin 代码托管（面向所有付费用户默认开启），8/19 让云端 Agent 自动订阅自己创建的 PR 并驱动到完成、在隔离 VM 上拉起子 Agent 并行围攻。**第二件事需要第一件事才成立**——一个要自动修 CI、回应 bot 评论、把 PR 推到合并的 Agent，需要对代码托管有远超「调 API」的控制权。于是 Cursor 的选择是**自己做托管**。同一周 GitHub 宕机 7 小时 47 分（15 天内第 7 起），恰好演示了「Agent 全自动流水线建在别人家地基上」的风险敞口。但社区的反应很能说明成熟度：讨论焦点**没有停留在「Origin 能不能打赢 GitHub」，而是迅速转向了「默认开启 + 数据条款未公布 + 编辑器/托管/模型三层垂直整合」**。这是个健康的信号——大家已经学会问「谁拥有这条数据流」，而不只是问「它跑得快不快」。Anthropic 这一周的动作恰好在另一个方向上：`headersHelper`（私有插件市场鉴权）、出口代理授权选项、企业网关校验扩展到 Remote Control、成本估算计入「仅美国推理」溢价——**同样是地基工作，但做的是「让 Agent 更好地跑在你自己的地基上」**。两条路线的分野，可能比任何 benchmark 都更能决定明年的格局。

**第三个信号更安静，但对每天用这些工具的人最实际：上下文预算正在从「模型的事」变成「工程的事」。** Claude Code 把内置 `claude-api` skill 的加载成本从 **20 万+ token 压到约 2.5 万**——降幅约 87%，手段不是换模型也不是删内容，而是**把参考文档改成按需加载**。这条之所以出圈，是因为它暴露了一个所有人都在踩的坑：这个 skill 会在项目引入 Anthropic SDK 时**自动激活**，受影响的用户根本不知道自己在为它付费。放在本周的另一个数字旁边看格外刺眼——`awesome-claude-skills` 已有 **72.9K stars、收录超一千个 skill**。当装几十个 skill 成为常态，**没有按需加载纪律的 skill 会在你敲下第一个字符之前就把预算吃光**。同理的还有 oh-my-pi 本周把全局 token 计数换成**模型作用域的 tokenizer**（多 provider 路由下终于按模型分别计算）、Codex 把预估成本直接显示进 `/status` 与终端标题、Claude Code 把「仅美国推理」的 1.1× 溢价计入成本估算。**这些全是同一件事：上下文与成本正在从一个模糊的后台数字，变成一个开发者需要主动管理、并且有工具可以管理的一等资源。** 上下文窗口越大，这件事越重要而不是越不重要——因为窗口大了之后，浪费它的代价才真正变得高昂。
