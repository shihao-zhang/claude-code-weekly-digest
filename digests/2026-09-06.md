## Claude Code 产品更新 (Claude Code Updates)

- **[Claude Fable 5.1 / Mythos 5.1 发布，Claude Code 同日集成 - 2026-09-01]** 本周 Anthropic 侧的主线：
  - **Fable 5.1**：1M 上下文、128K 最大输出。**输入 / 输出价格不变（$10 / $50 每百万 token），但缓存读取从 $1.00 砍到 $0.25（-75%）**。Anthropic 自估典型负载成本降约 25%，**复杂编码与高度 agentic 任务最多降约 45%**——这条价格结构的改动对"每回合重读同一份上下文"的 Agent 循环是直接的成本重写
  - 编码基准：**Terminal-Bench 4.0 55.8%**（Fable 5 为 42.0%，Opus 5 为 52.3%）；**Terminal-Bench-Science 0.1 从 Fable 5 的 24.7% 翻倍到 52.6%**（Opus 5 29.0%、GPT-5.6 Sol 22.4%）。注意：**Anthropic 并未公布 Fable 5.1 的 SWE-bench Verified 分数**，社区流传的"95%"来自第三方榜单；官方在 system card 里给的软件工程数字是 **SWE-bench Pro 81.2**，仅略微领先 Fable 5 与 Opus 5
  - **安全侧的重点不是更严，而是更松**：Anthropic 称 **网络安全类任务的误拦截（false positive）下降 60%，生物学类查询下降 85%**
  - **Mythos 5.1 是同一底座模型的受限访问版本**，面向经过审核的网络安全与生命科学组织，运行在更宽松的安全约束下——它在 Terminal-Bench 4.0 上是 **60.9%**，比 GA 版本高 5.1 个百分点，等于官方承认"**安全护栏本身要吃掉约 5 分能力**"
  - 可用性：Claude API、Amazon Bedrock、Claude Platform on AWS、Google Cloud、Microsoft Foundry；**在 Claude Code 里默认 High 努力等级**（Cowork / Claude.ai 为 Medium）

  ([Anthropic 官方公告](https://www.anthropic.com/claude-fable-and-mythos-5-1), [VentureBeat](https://venturebeat.com/technology/anthropics-claude-fable-5-1-and-mythos-5-1-arrive-with-a-75-cost-reduction-for-fable-cache-reads), [TechCrunch：更便宜也更少拒答](https://techcrunch.com/2026/09/01/anthropics-new-fable-release-is-cheaper-less-restrictive/), [Vellum 基准拆解](https://www.vellum.ai/blog/claude-fable-5-1-mythos-5-1-benchmarks-explained), [datasciencedojo 安全变更分析](https://datasciencedojo.com/blog/claude-fable-5-1-performance-and-safety/))

- **[v2.1.257 - Fable 5.1 接入 + auto mode 新增「Containment Escape」规则 - 2026-09-01]**
  - 新增 **Claude Fable 5.1**（1M 上下文，$10 / $50 每 Mtok）
  - **auto mode 新增 Containment Escape 规则**：**云元数据凭据获取、出网规避（egress evasion）、跨租户访问不再被自动批准**，除非环境显式标注为预期行为。这是 auto mode 上线以来第一条针对"沙箱逃逸类动作"的专门规则
  - 新增**首次读取工作目录之外文件前的一次性 auto mode 提示**；新增 `timeFormat` / `timeZone` 设置（12/24 小时制或 strftime）；`/effort` 新增 `s` 选项做**仅本会话**的变更；`/doctor` 会对被强杀会话遗留的**陈旧 sandbox mask 文件**告警
  - **破坏性变更：`defaultMode: "bypassPermissions"` 从此被忽略**；`--effort` 改为只抬升当前会话的默认值；`--add-dir` 拒绝网络路径；Claude apps gateway 启用证书 pinning
  - 修复一大批：`claude mcp remove` 残留 OAuth 凭据、遥测设置经托管设置下发被忽略、Remote Control 同意提示"点掉即视为同意"、Foundry 订阅仍附带残留 API key
  - 同日 **v2.1.258** 单独修复 **macOS 12 (Monterey) 无法启动**（2.1.255 引入的回归）

  ([v2.1.257](https://github.com/anthropics/claude-code/releases/tag/v2.1.257), [v2.1.258](https://github.com/anthropics/claude-code/releases/tag/v2.1.258), [DevelopersIO 解读](https://dev.classmethod.jp/en/articles/20260902-cc-updates-v2-1-258/))

- **[v2.1.259 - 托管 MCP、无人值守模式，以及一次很扎实的 deny 规则补漏 - 2026-09-02]**
  - 新增 **`managedMcpServers` 托管设置**：组织可以给所有用户下发 HTTP/SSE MCP server（条目格式同 `.mcp.json`，指定本地命令的条目会被跳过）
  - 新增 **`--permission-prompts none`**，用于无人值守的 headless 主机：任何会弹提示的动作**自动拒绝**，而当前权限模式（含 auto mode）继续正常裁决。这比"全放行"式的无人值守安全得多
  - **`Read()` deny 规则的一次系统性补漏**：此前不覆盖**作为选项值传入的文件**（`--ignore-revs-file=.env`、`-f.env`、`@file`）、`git diff` / `git grep` 的文件操作数、以及 `cd DIR && cat FILE` 这类复合命令；`grep -r` / `cp -r` 扫过含被拒文件的目录现在会询问
  - 修复**并发会话互相静默回滚 `~/.claude.json`**（工作区信任被重置、MCP / 项目状态丢失）——多开用户的老问题
  - 修复**关闭遥测的会话中 OAuth token 刷新会导致 prompt 缓存失效**
  - 安全：**托管设置文件 / drop-in / MDM plist / HKLM 值无法解析时，Claude Code 直接拒绝启动并指名是哪个源**——此前是静默不生效，等于策略形同虚设
  - **破坏性变更**：`allowedMcpServers` 改为只管用户自行添加的 server，此前被允许列表挡掉的 `managed-mcp.json` server 升级后会开始加载，需改用 `deniedMcpServers`

## Codex CLI 产品更新 (Codex CLI Updates)

- **[GPT-6 Astra 发布 - 2026-09-03]** 本周赛道最大的新闻，也是 Codex 的主线：
  - **模型 ID `gpt-6-astra`，1,050,000 token 上下文**（最大输入 922K、最大输出 128K），**$10 / $50 每百万 token，缓存输入 $1.00**——**价格是 GPT-5.6 Sol 的 2.5 倍**
  - OpenAI 总裁 Greg Brockman 称其为"generational leap"，并表示它最终可能被视为 AGI 的到来；研究副总裁 Aidan Clark 称这是迄今"**远超以往**"的最大训练运行，"**第一次在德州 Stargate 站点用超过 10 万张 GPU 做预训练**"
  - 招牌能力是 **computer use**（像人一样操作电脑）。**Terminal-Bench 4.0：Astra 57.7% vs Sol 37.3%**，20.4 个百分点的提升，是本次最亮眼的编码相关数字
  - **首个跨过 OpenAI Preparedness Framework「Critical」网络安全能力门槛的模型**：官方表述是在具备工具与访问权限时，它能**在无人逐步引导的情况下，于大量防护良好的系统上发现未知漏洞并开发利用手段**
  - 分阶段放量：**Pro / Enterprise / Business Premium 先在 ChatGPT Work 与 Codex 中拿到**，Plus 与其余 Business 用户随后数日跟进（9/5 更新）

- **[Astra 的安全门槛会误伤普通开发者，这是 Codex 用户本周最需要知道的一条]**

  - 新增**实验性上下文管理模式**：**不再把累积的工作反复压缩成一份摘要，而是跨上下文窗口保留笔记，并让更早的上下文窗口保持可检索**——Agent 可以回头找到之前消息与工具输出里的需求或测试结果。开启方式是在 `config.toml` 写入 `features.context_management.experimental_mode = true` 后开启新任务；**目前限于 Codex 后端的 Plus / Pro 会话**

## 实用技巧 (Tips & Tricks)

- **skill 装太多的，先跑一次 `/skill-doctor`。** 它会列出**没被用到的 skill 及其上下文开销**。四位数规模的 skill 生态里，未使用的 skill 不是"闲着不碍事"，而是每一轮都在吃 token。（Claude Code，[v2.1.261](https://github.com/anthropics/claude-code/releases/tag/v2.1.261)）

- **升到 v2.1.260 后，`/cost` 会告诉你缓存 miss 的可能原因。** 上期修的是"每小时掉一次缓存"这个具体 bug，这期给的是通用归因。配合 Fable 5.1 的 $0.25 缓存读取价，把缓存命中率调上去这件事本周的回报率是全年最高的。（Claude Code，[v2.1.260](https://github.com/anthropics/claude-code/releases/tag/v2.1.260)）

- **无人值守的 headless 主机改用 `--permission-prompts none`，别再用绕过权限的方案。** 它的语义是"**会弹提示的自动拒绝，权限模式继续正常裁决**"，而不是全放行。同期 `defaultMode: "bypassPermissions"` 已经在 v2.1.257 被**彻底忽略**了——如果你的 CI 还依赖它，本周就会静默失效。（Claude Code，[v2.1.259](https://github.com/anthropics/claude-code/releases/tag/v2.1.259) / [v2.1.257](https://github.com/anthropics/claude-code/releases/tag/v2.1.257)）

- **检查你的文件权限规则里有没有括号。** v2.1.260 修复了**含括号的规则被静默丢弃**，以及**单条无效规则会让全部编辑失效**——两个都是"规则写了但不生效/全挂"的静默故障，升级后建议重跑一遍 `/permissions` 确认。（Claude Code，[v2.1.260](https://github.com/anthropics/claude-code/releases/tag/v2.1.260)）

- **用 deny 规则保护 `.env` 的，v2.1.259 之前都有漏。** 此前 `Read()` deny 不覆盖**作为选项值传入的文件路径**（`--ignore-revs-file=.env`、`-f.env`、`@file`）、`git diff` / `git grep` 的文件操作数、以及 `cd DIR && cat FILE`。注意 v2.1.260 又**回滚了**把 deny 规则应用到 Bash 参数的部分做法——这块还在动，别把它当成唯一防线。（Claude Code，[v2.1.259](https://github.com/anthropics/claude-code/releases/tag/v2.1.259) / [v2.1.260](https://github.com/anthropics/claude-code/releases/tag/v2.1.260)）

- **Codex 跑长调试会话的，试试实验性上下文管理。** `config.toml` 里写 `features.context_management.experimental_mode = true` 再开新任务，Codex 会**跨上下文窗口保留笔记并让早期窗口保持可检索**，而不是反复压缩成一份摘要——正是"压缩会丢掉测试结果和早期需求"这个老痛点的正面解法。目前限 Codex 后端的 Plus / Pro 会话。（Codex CLI，[v0.153.0](https://github.com/openai/codex/releases/tag/rust-v0.153.0)）

- **Codex 用户注意：计划工具本周起默认关闭了。** 如果你的工作流依赖 `update_plan`，需要在配置里显式写 `tools.update_plan.enabled = true`。（Codex CLI，[v0.152.0](https://github.com/openai/codex/releases/tag/rust-v0.152.0)）

- **做安全相关工作的 Codex 用户，先评估 Astra 会不会挡你的活。** 标准访问会拒绝高级网络安全任务，**API 侧是直接终止而非暂停等审批**，且官方承认误伤会发生在**无关工作**中。要完整能力得申请 Daybreak。反过来，Claude 侧本周把网络安全类误拦截降了 60%，还有 Mythos 5.1 这条受审核通道——这是本周唯一一个"选型结论足够明确"的场景。（[BankInfoSecurity](https://www.bankinfosecurity.com/openai-launches-gpt-6-astra-tighter-cyber-safeguards-a-32745) / [TechCrunch](https://techcrunch.com/2026/09/01/anthropics-new-fable-release-is-cheaper-less-restrictive/)）

## 横向洞察 (Cross-cutting Insights)

**这一周，两家把「安全护栏」从工程细节推成了产品定位，而且给出的答案完全相反。** 同一个星期，同样的价格（$10 / $50），同样的 1M 级上下文，两个前沿模型相隔两天落地——但它们对"模型太强了怎么办"的处理方式几乎是镜像的。**OpenAI 的答案是锁**：Astra 是首个跨过 Preparedness Framework「Critical」网络安全门槛的模型，标准访问直接拒绝高级安全工作，API 侧是**终止任务而非暂停审批**，完整能力收进申请制的 Daybreak 计划，官方甚至提前承认普通用户会在**无关工作**中遭遇变慢、暂停或阻断。**Anthropic 的答案是拆**：Fable 5.1 把网络安全类误拦截降低 60%、生物学类降低 85%，同时把宽松版本单独命名为 Mythos 5.1，只给通过审核的网络安全与生命科学组织。最有价值的一个数字藏在这个设计里——**同一个底座模型，Mythos 5.1 在 Terminal-Bench 4.0 上 60.9%，Fable 5.1 是 55.8%**。这是行业第一次把"安全税"明码标价成约 5 个百分点。锁与拆各有道理，但**只有拆的那一方让外界能看见代价有多大**。

**第二条线：Coding Agent 的评测单位已经从「模型」彻底变成了「模型 + harness」，而这周的榜单第一次让这件事无法回避。** Artificial Analysis 的 Coding Agent Index 上，**Fable 5.1 跑在 Claude Code 里拿 70，Astra 跑在 Codex 里拿 67**；同一批模型在 Intelligence Index 上是 65.7 对 61.2；而在 OpenAI 自己的基准里 Astra 领先，Terminal-Bench 4.0 上对 Sol 是 57.7% 对 37.3% 的碾压。这些数字**没有一个是错的**，它们只是在测不同的东西。Simon Willison 把这个张力总结为"同价、自报基准更高、第三方指数更低"；HN 上更直白——"第一张图：从 61 到，鼓声，61"。同一周传得最广的"Fable 5.1 SWE-bench Verified 95%"根本不是 Anthropic 发布的数字（官方只在 system card 里给了 SWE-bench Pro 81.2）。**当 harness 能贡献几个点、榜单口径能贡献十几个点、二手传播还能凭空造出一个分数，"哪个模型更会写代码"这个问题已经不再有单一答案**——它取决于你用哪个 CLI、跑什么任务、看谁的表。这也解释了为什么两家 CLI 本周的更新重心都不在"接新模型"上，而在**上下文管理、缓存归因、输出预算**这些 harness 层的东西：模型差距在收窄，harness 差距在放大。

**第三条线：上下文工程本周出现了第一次真正的路线分叉。** 长期以来所有工具处理"上下文满了"的方式都是同一个——**压缩成摘要**，代价是丢细节。Codex v0.153.0 的实验性上下文管理给了另一个答案：**跨窗口保留笔记，并让更早的上下文窗口保持可检索**，Agent 可以回头去找之前的需求或测试结果，而不是依赖一份被压扁的摘要。这不是参数调优，是**从"有损压缩"换到"外部化 + 检索"**的架构切换。同一周 Claude Code 的动作看似无关，其实在同一条线上：`/skill-doctor` 量化未使用 skill 的上下文成本、`/cost` 显示缓存 miss 的归因、`bashOutputMaxChars` / `taskOutputMaxChars` 把命令输出上限交给用户，而 Codex 反向给**单个 MCP 工具**加了 `output_token_limit`。**两家在同一周从相反方向拧同一个旋钮，说明"上下文里到底该放什么、放多少"正在从模型的隐含行为，变成产品必须显式暴露的配置面。** 再叠上 Fable 5.1 把缓存读取砍到四分之一——**上下文从此既是能力约束，也是成本变量，还是可编程对象**。谁先把这三重身份统一成一套连贯的心智模型，谁就能在下一轮"模型差距不大"的竞争里赢下 harness 这一层。
