## Claude Code 产品更新 (Claude Code Updates)

- **[Auto Mode 成为默认权限模式 - 2026-08-14]** 本周（也是今年迄今）Claude Code 最具结构性的一次变更——**审批权从人手里交给了分类器**：
  - 从 **8 月 14 日起，Pro / Max / Team 计划的新会话默认进入 auto mode**。Claude 会持续推进，除非某个动作被判定为**不可逆、破坏性、或指向你自身环境之外**
  - 实现上是**两级分类器**：一个快速前置过滤器处理绝大多数工具调用，让安全动作以最小开销放行；只有落入可疑区间的调用才进入更重的判定
  - Anthropic 给出的核心论据是一组对比数据：在 **1,053 名付费测试者**的研究中，人类只拦下了 **13.6%** 的危险命令，而 auto mode 拦下了 **89%**；同时用户对权限弹窗的批准率高达约 **97%**——换句话说，官方的论证不是「AI 审得更好」，而是「**人类审批这道防线事实上已经失效**」
  - 第三方红队把分类器的漏判率从 **12% 压到 7%**；Anthropic 同时补上了 prompt-injection 筛查、可配置 deny 规则，以及防止敏感数据被移出授权环境的保护
  - 分类器会给每次工具调用增加少量 token 开销，但 **Pro / Max / Team 用户不再为这部分开销付费**
  - **Enterprise、Claude API、Anthropic Platform、Amazon Bedrock、Google Cloud Agent Platform、Microsoft Foundry 仍为 opt-in**，官方计划在接下来一个月内逐步铺开
  - Anthropic 自己援引的收益数据：使用 auto mode 的团队比走人工审批的团队**多交付约 25% 的 PR**

## 社区热点 (Community Highlights)

- **[Auto Mode 默认化成为本周最大争论：「人类审批已经失效」这个论证站得住吗？]** Anthropic 把默认权限交给分类器，社区反应明确地**混合**而非一边倒：
  - **支持方接受了数据**：13.6% vs 89% 的拦截率对比、97% 的弹窗批准率，实质是在说人工审批已经退化成肌肉记忆点击。The New Stack 的标题把这层意思说白了——「Auto Mode 将成为 Claude Code 默认，因为人类不可信」
  - **反对方的核心不是「AI 不如人」，而是拓扑问题**：把审批集中到一个分类器，等于制造了**单点故障**——一旦被绕过，Agent 就能在完全无人工审批的情况下执行有害操作。安全研究者最担心的一类，恰恰是**藏在 Agent 从外部读入的内容里的攻击**（间接注入），而这正是分类器最难覆盖的面
  - 也有研究者直接要求**独立复现**：安全性声明目前主要来自厂商自己的测试与红队，缺少第三方验证
  - 值得记的一个细节：Anthropic 同日发布的 **v2.1.233 专门修了「auto mode 在普通 Bash 命令上反复停下来要人工批准」**——默认化前一天还在调分类器的松紧度，本身就说明这条曲线不好走

  ([The New Stack](https://thenewstack.io/claude-code-auto-mode/), [Help Net Security](https://www.helpnetsecurity.com/2026/08/10/anthropic-claude-code-auto-mode/), [The Register](https://www.theregister.com/ai-and-ml/2026/08/10/claude-code-puts-auto-mode-in-the-drivers-seat/5285326), [DevOps.com](https://devops.com/anthropic-makes-claude-codes-auto-mode-the-default-betting-automation-beats-manual-review/), [Simon Willison](https://simonwillison.net/2026/Aug/8/auto-mode/))

- **[Black Hat USA 2026 后续发酵：一个 GitHub issue 打穿三家厂商的 CI secrets]** 本周安全侧的主线，是 8/5 Black Hat 披露在 8/8 CSA 研究简报发布后的持续扩散：
  - Novee Security 的 Elad Meged 演示：一个**没有任何仓库权限的外部账号**开的 GitHub issue / PR 标题，就足以同时劫持 **Anthropic 的 Claude Code Security Review agent、Google 的 Gemini CLI Action、GitHub 的 Copilot Coding Agent**——三者都在厂商自家仓库中泄露了 API key、GitHub token 与云凭据

## 实用技巧 (Tips & Tricks)

- **用 `@` 直接把另一个会话拉进当前对话（Claude Code v2.1.232）**：在 prompt 里输入 `@` 就能按名字 @ 另一个 Claude 会话，Claude 会用 `SendMessage` 联系它。配合本版新增的「同机会话名称唯一化」和 `/config` 里的 "Messages from your other sessions"（accept / hold / refuse），跨会话协作第一次有了可用的寻址与准入两件套。之前要靠 ref 才能精确投递，现在裸名字唯一匹配即可直达。([Release v2.1.232](https://github.com/anthropics/claude-code/releases/tag/v2.1.232))

- **fork 型子 Agent 现在默认开启，省掉重复的信息收集（Claude Code v2.1.232）**：`subagent_type: "fork"` 的子 Agent **继承完整会话与 prompt cache**——意味着它不必从零重新读一遍你已经让主 Agent 读过的代码。对长会话里的「派个分身去验证一下」类任务，这是直接的成本与延迟改善。同时交互式会话中的非 teammate agent 默认后台运行，不再阻塞你继续对话。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **别再让 `/commit-push-pr` 替你自动批准危险 git 标志（Claude Code v2.1.229）**：这一版起 `/commit-push-pr` 不再自动放行危险 git 标志。如果你之前是靠「这个命令反正被 allowlist 了」的心智在用它，现在会开始看到弹窗——这不是回退，是把 force-push 一类操作从「隐式批准」拉回「显式批准」。auto mode 默认化的背景下，这类**显式收紧**比新功能更值得留意。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **给失控的 Bash 命令加内存天花板（Claude Code v2.1.233）**：Linux 上新增 opt-in 的 memory cgroup 支持。跑 Agent 生成的构建 / 测试脚本时，一个内存泄漏的子进程就能把开发机拖垮；开启后可以给 Bash 工具命令套上限。同版本还加了 `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`——反复抓同一批文档时，把 TTL 调长可以显著省掉重复请求。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **AGENTS.md 放到它描述的代码旁边（Kiro CLI 2.18）**：Kiro 现在从 workspace 树的任意位置加载 AGENTS.md 作为 steering context。这个模式值得跨工具借鉴：与其在根目录维护一份包罗万象、越写越长、注意力被稀释的说明文件，不如把「这个模块为什么这么写」放在模块目录里——Agent 读到那个目录时它自然生效，读不到时也不占上下文。([Kiro CLI 2.18](https://kiro.dev/changelog/cli/2-18/))

- **脚本化工作流里用显式 `@plugin` 调用（Codex CLI v0.147.0）**：Codex 的插件既可以隐式触发（描述你想要的结果），也可以用 `@` 加插件名显式调用。**在确定性重要的脚本化工作流里，显式调用明显更可取**——隐式触发依赖模型的判断，同一份脚本两次跑可能走上不同路径。另外注意 `codex exec --full-auto` 已移除，改用 `--sandbox workspace-write`。([Codex CLI v0.147.0 解析](https://codex.danielvaughan.com/2026/08/10/codex-cli-v0147-portable-agent-plugins-multi-catalog-federation-approve-for-me-conversation-sections/), [cheat sheet](https://toolsbase.dev/en/reference/codex-commands))

- **抄官方 reference workflow 之前先读一遍威胁模型（跨工具）**：CSA 发现 100+ 公开仓库因为直接照抄 Anthropic / Google / OpenAI 的 reference workflow 而带上了同一个可被外部 issue 触发的 CI 密钥泄露面。**厂商的示例 workflow 是能力演示，不是安全基线**。最低限度的动作是：给 Agent 触发的 workflow 单独发权限最小化的 token，并对外部贡献者输入加人工审核门。([CSA 研究简报](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-cicd-secrets-20260808-csa/))

## 横向洞察 (Cross-cutting Insights)

**这一周的主题只有一个：审批权的所有制变更。** Anthropic 8/14 把 auto mode 设为 Pro / Max / Team 的默认，理由不是「AI 审得更好」，而是一组更难反驳的数据——人类只拦下 13.6% 的危险命令，弹窗批准率 97%。翻译过来是：**人工审批这道防线在统计意义上已经不存在了，它只是仍然存在于产品截图里**。这个论证之所以重要，是因为它把整个赛道过去两年的默认设计判为无效。Codex 的 `--approve-for-me`（opt-in 派一个 reviewer 子 Agent 过滤审批）和 Anthropic 的 auto mode（默认走两级分类器）是同一件事的两个进度条位置，OpenAI 甚至在同一周补上了「对 cyber-capable 模型应用更安全的自动审批默认值」——两家都在往同一个方向走，只是 Anthropic 先按下了默认开关。但要看清代价：把审批集中到分类器，意味着**从「一百万个疲惫的人类各自误判」换成了「一个分类器统一误判」**。前者是弥散的、无相关性的失效；后者是可被针对性研究、可被一次性绕过的单点。安全研究者要求独立复现，要的正是这个。

**而 CSA 的披露恰好证明了单点为什么危险，也证明了真正的攻击面根本不在审批那一层。** Black Hat 上的演示里，一个没有任何仓库权限的外部账号，用一个 issue 标题就同时打穿了 Claude Code、Gemini CLI、Copilot 三家的 CI secrets——这类攻击的载体是 **Agent 从外部读进来的内容**，它在被读入时看起来完全正常，危险性只在后续的动作链里才显形。分类器擅长判断「这条命令危不危险」，不擅长判断「这段我刚读到的文本是不是在操纵我」。更值得警惕的是扩散机制：CSA 找到一百多个公开仓库带着同一个漏洞，**不是因为它们都犯了同一个错，而是因为它们都抄了同一份官方示例**。这意味着在 Agent 时代，一份 reference workflow 的默认值就是一个供应链投放渠道。这也解释了 Claude Code 本周补丁的分布——PowerShell 的 `$PSDefaultParameterValues` 覆写、Git Bash 跟随 Cygwin 软链、Windows NT `\??\` 设备前缀绕过 UNC 校验、嵌套 git 仓库继承父目录信任——**全是「合法输入的非常规写法」**，没有一个是逻辑错误。审批模型可以自动化，但边界枚举不行，它只能靠一周一周地补。

**能力在收敛，差异化正在下沉到编辑原语和权限模型这两个更底层的地方。** 本周两个看似无关的数字放在一起看很有说服力：Google 的 Gemini **3.7 Flash**——一个 Flash 档位、引荐价 $0.75/$3.75 的模型——把 Terminal-Bench 2.1 做到了 **85.8%**，已经贴到 Claude Opus 5 + Claude Code 的 86.7%；与此同时，一个 25K stars 的开源 fork **oh-my-pi** 靠的完全不是模型，而是 **hash-anchored edits**（把编辑锚定到内容哈希而非行号，让并行 Agent 的冲突立刻暴露而非静默损坏）和真正接进 LSP / DAP 的符号级操作。上层模型能力正在快速商品化——**顶级分数不再是护城河，因为下个月就有一个便宜十倍的模型贴上来**；而「两个 Agent 同时改一个文件会发生什么」「rename 到底是不是真的 rename」这类问题，至今没有任何一家给出标准答案。社区共识的演化路径也印证了这点：一万多条 Reddit 评论收敛出的结论不是选谁，而是「Codex 当苦力、Claude Code 当大脑」的分工——**当用户开始按能力特征而非品牌来编排多个 Agent 时，护城河就必然从模型迁移到运行时**。这与上期观察到的跨 Agent 记忆层是同一条线：会话状态、消息传递、并发编辑冲突——这三样今天各家各造，两三个季度后大概率会长出一层标准。
