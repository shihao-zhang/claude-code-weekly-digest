## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.287 - Claude Mods：插件可以改写 Claude Code 自己 - 2026-10-01]** 本周最重要的一条，也是 Claude Code 自 plugin / skill 之后最大的扩展模型变更。
  - **是什么**：mod 是**跑在 Claude Code 进程内部**的 JavaScript / TypeScript 事件处理函数。一个 mod 最少三个文件（`plugin.json` + `hooks.json` + `register.js`），用 `register(on)` 注册 hook，Claude Code 在事件发生时调用它，hook 可以**观察（observe）/ 改写（rewrite）/ 接管（answer）**该事件
  - **能做到旧机制做不到的四件事**：① 画界面——transcript 旁的 pane、提示框上方的 band，带 tab / 按钮 / 文本框；② **重绘 Claude Code 自己画的东西**——工具调用行、spinner、提问对话框；③ **介入工具调用或请求**——挂住一个工具调用去问用户、不跑工具直接作答、把某个请求发给另一个模型；④ 注册**立即执行的 `/command`**（不走 Claude 回合，Claude 正在工作时也能跑）
  - **官方示例只有 15 行**：`on('tool.call', …)` 累加计数，`on('ui.render', {component:'Spinner'}, …)` 把计数拼到 spinner 后面，输出 `Thinking · tool calls: 3…`
  - **安全模型是这次最该读清楚的部分**：mods **不沙箱**，以你的权限运行——可读写你账号能访问的任何文件、起进程、发网络请求、**读环境变量与配置文件里的 API key**、看到你每一条提示词与每一次工具调用、改写提示词、**在你被问之前就批准工具调用**（包括 `ask` 规则会拦的、以及你自己的 `PreToolUse` hook 已经拦下的）、花你的额度。打开 Claude Code 的 sandbox **不管用**——沙箱隔离的是 Claude 跑的 Bash 命令，mod 自己起的进程在沙箱外。唯一它改不了的是**权限提示框本身**
  - **安装前可审计**：`claude plugin validate ./some-mod` 输出里的 `hooks:` 与 `calls:` 两行会列出它监听哪些事件、要求 Claude Code 做哪些事（读文件、发网络请求等），**不运行代码**
  - **关掉的三档**：单个 mod 在 `/plugin` 里 disable；一次会话用 `--safe-mode`；全局 `"disableAllHooks": true`。组织侧有 `allowManagedModsOnly`
  - **Anthropic 把自家功能重写成了 mod**：内置 mod 列表里有 `cc-plugin-agents-md`（加载 `AGENTS.md` 作为项目指令）、`cc-plugin-diff`（接管 `/diff` 并画它的 pane）、`cc-plugin-sec-default`（在托管机器上守住组织配置不被用户装的 mod 推翻）、`cc-plugin-telemetry`、`cc-plugin-plugin-authoring`。其中 `diff` / `agents-md` / `sec-default` / `telemetry` 的**源码已公开**
  - **运行范围不等于绘制范围**：终端与桌面端 Code tab 两者都有；**VS Code 扩展、`claude -p`、Agent SDK、云端会话里 hook 会跑但画不出来**；Desktop 的 WSL 会话完全不加载
  - 早期试用的 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` 已被忽略，设成 `0` 也挡不住

  ([Mods overview 官方文档](https://code.claude.com/docs/en/plugins/mods/overview), [官方博客 Customize Claude Code with mods in TypeScript](https://claude.com/blog/claude-code-mods), [changelog v2.1.287](https://code.claude.com/docs/en/changelog), [官方示例 mods（claude-code-playground）](https://github.com/anthropics/claude-code-playground/tree/main/claude-code/mods), [内置 mod 源码](https://github.com/anthropics/claude-code/tree/main/mods))

- **[Claude Sonnet 5.5 的五个破坏性变更 - 2026-09-28]** 和上期 Opus 5.5 一样，这部分是 API 层的，但对写 harness / skill / CLAUDE.md 的人是直接影响：
  - **关掉前置思考改用 `between_tools`**：`thinking: {"type":"disabled"}` 返回 400 并在错误信息里指向 `between_tools`。`between_tools` 是这个模型上**最低的思考档**，只在 `low` / `medium` / `high` effort 下接受，**`xhigh` / `max` 下传它直接 400**；它也不接受 `display` / `budget_tokens` / `block_binding`，且**用它时 effort 不能在对话中途改**。注意与 Opus 5.5 的对比：Opus 5.5 **根本不能关 thinking**，Sonnet 5.5 把这个口子留了回来
  - **不支持强制工具调用**：`tool_choice` 的 `any` 与 `tool` 返回 400（token counting 端点同样），改用 `auto` + strict tool use 或 structured outputs
  - **thinking block 绑定到模型与对话**：每个 thinking block 记录produce 它的模型。Sonnet 5.5 能读 Sonnet 5 / Opus 4.8 / Haiku 4.5 及更早的块，**但读不了 Opus 5 / Opus 5.5 / 任何 Fable 或 Mythos 的块**；反过来，**Opus 5.5 能读 Sonnet 5.5 的块（仅 Claude API 与 Google Cloud），别的模型都不能**。读不了的块 API 会在模型看到前丢掉（请求成功、丢掉的块不计费）。更硬的一条：API 还会检查 thinking block 产生之后 `system` / `tools` / 更早的消息**有没有被改过**，**对 2026-08-31 00:00 UTC 及之后创建的账号默认强制执行**，改过再回放就是 400——**结论是对话必须 append-only**，改指令或改工具要走 mid-conversation system message 而不是编辑历史
  - **`computer_20251124` 在 Claude API 与 Google Cloud 上被拒**（Bedrock 仍接受），改用 `computer_toolset_20260801`
  - **advisor 工具配对收窄**：Opus 4.8 / Opus 4.7 / Sonnet 5 不能再做 Sonnet 5.5 executor 的 advisor（400）；Sonnet 5.5 接受的 advisor **一律返回加密的 `advisor_redacted_result`**，客户端读不到建议原文
  - 另有一条不报错但改变响应形状的：**工具调用之间的叙述文本改从 `thinking` block 返回**（默认 `display: "omitted"` 下为空，只渲染 `text` 的客户端会在工具调用之间「静音」），和上期 Opus 5.5 是同一个坑
  - **新增一条帐号级约束**：Sonnet 5.5 产生的 thinking block **只在产生它的账号（或关联账号）里有效**，别的账号发过来会被丢掉

  - **Codex Security Cloud**：常开的应用安全服务——**按需或按计划扫整个 GitHub 仓库**（不限于单文件、单 PR 或某个时点快照）、持续跟进新提交、去重、在云端起草修复交人审；**默认带上 Daybreak Blue 这一档 cyber-capable 模型，不再需要单独申请 Daybreak**；官方称每条发现会先尝试在隔离环境里实际利用一次，**在沙箱里跑不通的不进列表**。开放给 Pro / Business / Enterprise / Edu（桌面端与网页端）

  - **Agents API 支持 computer use**，并把 Codex 的多 Agent、tool search、tool calling、上下文压缩能力开放进应用

## 实用技巧 (Tips & Tricks)

- **装任何 mod 之前先跑 `claude plugin validate ./some-mod`**（Claude Code）。输出里的 `hooks:` 列出它监听哪些事件，`calls:` 列出它要求 Claude Code 做什么（读文件、发网络请求、调模型……），**整个过程不执行它的代码**。这是目前唯一的静态审计手段，本周所有安全清单的第一条都是它。([Mods overview](https://code.claude.com/docs/en/plugins/mods/overview))

- **不用自己写 mod——让 Claude 写**（Claude Code）。官方的推荐路径就是在会话里描述你想要什么，Claude 写 TypeScript、装上、**在当前会话热重载**。内置的 `cc-plugin-plugin-authoring` 提供 `plugin-authoring` skill 专门做这件事。想先看成品的，官方在 `claude-code-playground` 放了三个完整示例：`token-weather`（提示框上方画上下文窗口「天气预报」）、**`blast-radius`（挂住 `rm -rf`、force push 这类危险命令，先展示它会改什么，再给「继续 / 取消」按钮）**、`replay-theater`（`/replay` 逐步回放上一回合的文件编辑）。用 `--plugin-dir` 可以只为一次会话加载。([Create a mod](https://code.claude.com/docs/en/plugins/mods/create), [示例 mods](https://github.com/anthropics/claude-code-playground/tree/main/claude-code/mods))

- **怀疑 mod 在捣鬼时，三档关法按范围选**（Claude Code）：单个 mod 在 `/plugin` 的 Installed 里 disable；**一次会话用 `--safe-mode`**（同时关掉你其它所有自定义）；**所有会话用 `"disableAllHooks": true`**（settings hook 与自定义状态栏一起停，组织托管的仍然跑）。`/plugin` 的 tab 下方那行 `1 mod active · first-mod` 是确认当前加载了什么的最快办法。([Mods overview · Turn mods on or off](https://code.claude.com/docs/en/plugins/mods/overview))

- **迁到 Sonnet 5.5 时，先把 effort 重新扫一遍，别搬 Sonnet 5 的设置**（Claude API / Claude Code）。官方明确说 effort 等级**被重新标定过**：起点建议是 `high`，除非工作是 agentic 或对延迟敏感；**agentic coding 与多步工具调用从 `medium` 起步**，难的或长的再上 `high`；聊天类从 `medium` 或 `low`。另外别忘了对应的 `/doctor prompt-audit`（上期上线）——它正是干这件事的。([Prompting Claude Sonnet 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5-5), [What's new · Behavior differences](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5))

- **用 Sonnet 5.5 的话，把对话改成 append-only**（Claude API）。它的 thinking block 绑定到 `system` + `tools` + 更早的消息，**2026-08-31 之后创建的账号默认强制校验**，改过历史再回放就是 400。要改指令或改工具，走 **mid-conversation system message**；要加工具，用 `inline-tools-2026-09-15` beta 的 `tool_addition`（不动 `tools`、不掉 prompt cache）；要压上下文，用 `compact-2026-09-04` 的按需压缩（保留的回合里的 thinking 在条件满足时仍然有效），而不是自己剪历史。([Thinking blocks are tied to the model and the conversation](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5#thinking-blocks-are-tied-to-the-model-that-produced-them), [Preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking))

- **项目里放一个名叫 `verify` 的 skill**（Claude Code v2.1.286+）。只要项目或用户 skill 里存在名为 `verify` 的 skill，Claude 就会被告知**在提交之前运行它**（docs-only 与 tests-only 提交除外）。这是把「提交前校验」从 CLAUDE.md 里的一句叮嘱变成约定的最省事做法。([changelog v2.1.286](https://code.claude.com/docs/en/changelog))

- **`/code-review --max-findings <n>|all`**（Claude Code v2.1.288+）。默认的发现数上限之外可以要更多或更少，而且**这个选择会一直沿用**，直到你传 `--max-findings default`。另：`claude project purge` 已改名 **`claude purge`**（旧名仍可用但会提示）。([changelog v2.1.288](https://code.claude.com/docs/en/changelog))

- **Codex 侧：打开 `instant_interrupt`**（v0.159.0+，可选开启）。模型正在出响应、或长 code-mode 调用正在跑的时候，新输入可以**直接改方向**而不必等回合结束——对「看着它跑偏」这个最常见的痛点，这是本周最实用的一个开关。([GitHub release rust-v0.159.0](https://github.com/openai/codex/releases/tag/rust-v0.159.0))

## 横向洞察 (Cross-cutting Insights)

**两家在同一周对「客户端」做了方向完全相反的手术。** Anthropic 把 Claude Code 的进程打开了：mods 是跑在它自己进程里的第三方 TypeScript，可以改写提示词、接管工具调用、重绘界面，**不沙箱、默认开启**；更彻底的是 Anthropic 把自己的 `AGENTS.md` 加载和 `/diff` 面板也重写成了内置 mod，并公开源码——这不是「开放了一个扩展点」，这是**把客户端的内部结构变成公共 API**，自家功能从此和第三方 mod 跑在同一条管道上。OpenAI 在 DevDay 走的是反向：Codex Cloud 把任务搬进可复用的云端环境、Code Review 进 ChatGPT 收件箱、Security Cloud 常驻扫整个仓库——**本地那个进程在这套叙事里越来越像一个遥控器**。有意思的是 DevDay 还把「全新 Codex CLI」端成一条公告，但里面的语音、`/agents`、`/usage`、worktree、Mermaid 渲染基本都是过去三周 v0.155–0.157 已经逐版发出去的；**需要把既有发布重新打包成叙事，本身就说明 CLI 不再是它这次想讲的主线**。而最锋利的一票来自第三方：DeepSeek Harness 在 Mods 发布两天后（10/3）就放出了实验性 **Claude Code Mods 兼容层**——第三方在用脚投票，它们认为「可改写的本地客户端」是接下来要兼容的那个接口标准，而不是云端。

**模型层继续往回收权，但这次收得不均匀，而且 harness 的账单越来越清楚。** 上期 Opus 5.5 一次收掉四个旋钮（thinking 不能关、不能强制工具调用、不能 prefill、不能调采样参数）；本周 Sonnet 5.5 **把其中一个口子还了回来**——新增 `between_tools` 作为最低思考档，默认 effort 还是 `high`（Opus 5.5 是 `medium`）。一周之内同底座两款模型在同一个旋钮上给出相反答案，说明「收掉控制权」目前还是逐模型做取舍，不是已经定下的平台方针。但 Sonnet 5.5 同时加了一道**比旋钮更硬的约束**：thinking block 绑定到模型、绑定到对话（`system`/`tools`/更早消息改过就 400，**2026-08-31 后创建的账号默认强制**）、还绑定到**账号**。这三层绑定合起来等于一条新规矩：**对话历史从此是 append-only 的、是有主的、是不可搬运的**。谁在为此付账很清楚——Claude Code 本周连着三版（287 修 Opus 5.5↔Sonnet 5.5 切换时改写早先 MCP 公告导致丢思考、288 修「恢复 2.1.286 或更早的会话丢掉早先思考」、以及 resume 丢文件丢回复的一串）几乎整版在吸收这件事，官方的两个 beta（按需压缩、在消息里定义工具）也正是为了让 harness 在不剪历史的前提下还能压上下文、还能改工具。**模型越不肯让 harness 碰它的中间状态，harness 就越需要官方给出的「合法修改姿势」**——这才是这一周真正的 API 变化。

**同一周最反直觉的一条是：中端模型在 agentic coding 上开始压过旗舰。** Sonnet 5.5 的 Terminal-Bench 4.0 **70.6% 反超六天前刚被设为 Claude Code 默认的 Opus 5.5（66.4%）**，GDPval-AA 几乎打平（1844 vs 1846），价格只有一半；OpenAI 这边 GPT-6.1 Sol 以 $2/$10 在 DeepSWE 上追平 Astra，Terminal-Bench Science 的 max effort 档每任务 $5.47 对 Astra $23.80、Opus 5.5 $23.21。两家在同一周给出同一个结论：**「旗舰档位」在 agentic 编码这个具体场景上的溢价正在被自家的中端产品打穿**。它带出的两个具体后果已经可见——Cline 在 GPT-6.1 Sol 发布次日就把它设为多家 provider 的默认模型，而 Claude Code 虽然 9/22 刚把 Pro/Team Standard 的默认从 Sonnet 改成 Opus、本周接入 Sonnet 5.5 时却**没有把这个默认改回去**。另一条暗线是信任：auto mode 本周成为交互式终端与 VS Code 在**所有档位、所有 provider** 上的默认权限模式（v2.1.284），`claude -p` 与 Python SDK 紧跟（v2.1.285），**审批权正在系统性地交给分类器**；而同一周上线的 mods 可以**在你被问之前批准 `ask` 规则本该拦下的调用、甚至批准你自己的 `PreToolUse` hook 已经拦下的调用**。一边把人从审批环节移走，一边把审批接口交给不沙箱的第三方代码——**v2.1.289 在发布次日就修掉「用户装的 mod 的批准盖过托管 deny 规则」这个洞，大概不会是最后一个**。
