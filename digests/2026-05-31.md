## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.152 - /code-review --fix + 技能管理强化 - 2026-05-26]** 本周第一个重量级版本，共含 33 处改动，其中 8 项新功能：
  - **`/code-review --fix`**：Code review 完成后可直接将简化、复用、效率改进建议应用至工作区，无需手动复制修改；`/simplify` 现在内部调用 `/code-review --fix` 作为别名
  - **`/reload-skills`**：新增技能热重载命令，无需重启 Claude Code 即可刷新本地技能定义
  - **`disallowed-tools` 技能前置配置**：可在技能的 YAML frontmatter 中声明 `disallowed-tools`，该技能激活时自动屏蔽指定工具，适合需要严格限制工具调用范围的安全敏感场景
  - 修复会话切换模型或重新登录后无响应的问题
  ([GitHub Release v2.1.152](https://github.com/anthropics/claude-code/releases/tag/v2.1.152), [DevelopersIO 分析](https://dev.classmethod.jp/en/articles/20260524-claude-code-updates-v2-1-152/))

- **[v2.1.153 - 后台会话稳定性 + /model 默认保存 - 2026-05-27]** 36 处改动，重点强化后台 Agent 可靠性：
  - **`/model` 保存策略调整**：选择模型后默认保存为新会话的全局默认值；按 **S** 键可切换为仅当前会话生效
  - **`/resume` 支持后台会话 + 耗时通知**：恢复任务时展示已运行时长（elapsed duration），方便快速感知任务进度
  - **skipLfs 选项**：GitHub/Git 插件市场来源新增 `skipLfs` 配置，可跳过 Git LFS 下载，对大型仓库的安装速度提升明显
  - **COLUMNS/LINES 环境变量透传**：现在将终端尺寸变量传递给 status line 命令，使自定义状态栏能正确适配终端宽度
  - 安全修复：针对 MCP 和认证流程的安全加固
  ([GitHub Release v2.1.153](https://github.com/anthropics/claude-code/releases/tag/v2.1.153), [DevelopersIO 分析](https://dev.classmethod.jp/en/articles/20260528-claude-code-updates-v2-1-153/))

- **[v2.1.154 - 划时代更新：Opus 4.8 + Dynamic Workflows 研究预览 - 2026-05-28]** 本周乃至本月最重要的版本，44 处改动，两项重磅功能同步落地：
  - **Claude Opus 4.8 成为 Claude Code 默认模型**：高努力等级（high effort）开箱即用，`/effort xhigh` 可激活超高强度模式；已弃用 `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` 环境变量（计划 6 月 1 日移除）

  ([GitHub Release v2.1.154](https://github.com/anthropics/claude-code/releases/tag/v2.1.154), [DevelopersIO 分析](https://dev.classmethod.jp/en/articles/20260529-claude-code-updates-v2-1-154/), [Dynamic Workflows 官方文档](https://code.claude.com/docs/en/workflows), [Anthropic 公告](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code))

## 实用技巧 (Tips & Tricks)

- **`/code-review --fix` 实现"审查+修复"一步到位（Claude Code）**：完成代码审查后，追加 `--fix` 标志即可让 Claude 直接将简化、复用和效率建议应用至工作区，无需逐条手动修改；适合 PR 前的代码质量终检流程。([GitHub Release v2.1.152](https://github.com/anthropics/claude-code/releases/tag/v2.1.152))

- **`/model` 按 S 键控制生效范围（Claude Code v2.1.153）**：选模型时按回车默认保存为全局新会话的默认值；若只想临时切换当前会话而不影响以后的会话，在确认前按 **S** 键选择"Session only"。([GitHub Release v2.1.153](https://github.com/anthropics/claude-code/releases/tag/v2.1.153))

- **本地技能无需发布直接用（Claude Code v2.1.157）**：将技能目录放进项目的 `.claude/skills/` 即可自动加载，无需通过插件市场安装。适合团队内部快速共享实验性 skill，或在正式发布前的本地开发迭代。([GitHub Release v2.1.157](https://github.com/anthropics/claude-code/releases/tag/v2.1.157))

- **Dynamic Workflows 最佳触发时机（Claude Code）**：工作流适合任务可并行分解的大型场景（多文件重构、全量端对端测试生成、跨仓库迁移），当前仍处研究预览阶段，不建议在需要精确中途干预的任务中单独依赖 workflow，搭配多轮 code-review 周期效果更佳。([Dynamic Workflows 文档](https://code.claude.com/docs/en/workflows))

- **Codex CLI Vim 文本对象编辑（Codex CLI v0.135.0）**：v0.135.0 的 Vim 模式新增完整文本对象支持（`diw` 删除单词、`ci"` 改写引号内容等），习惯 Vim 操作的开发者现在可以在 Codex TUI 内使用与编辑器相同的肌肉记忆。([GitHub Releases - openai/codex](https://github.com/openai/codex/releases))

## 横向洞察 (Cross-cutting Insights)

**本周最重要的事件不是一个功能，而是一个架构范式的转移：Dynamic Workflows 的发布，标志着 AI coding 进入"Agent 编排操作系统"时代**。此前的 multi-agent 模式本质是人工设计任务图，再分发给多个 Claude 实例；而 Dynamic Workflows 让 Claude 自己写编排脚本——这将"要不要并行"的决策权从人转移给了模型。Bun 的 Zig→Rust 迁移案例（75 万行、11 天）是迄今为止对"AI 能承接多大工程工作"最有力的公开证明，同时也清晰划定了当前边界：工作流仍需人工事后审查，且中途干预机制尚不成熟，HN 讨论里的核心焦虑正在这里。这是 Anthropic 今年最大的产品赌注。

**Opus 4.8 的发布节奏本身是一个信号**：距离 Opus 4.7 仅 41 天，但 Anthropic 选择维持定价不变，将成本优化（Fast Mode 降价 3 倍）和性能提升（SWE-bench Pro +4.9 分，领先 GPT-5.5 约 10 分）同时推出。与此同时，Anthropic 着力宣传的不仅是基准分数，而是"4 倍减少自身代码缺陷放行"的对齐改进。这说明 Anthropic 的竞争叙事正在从"最强 benchmark"迁移向"最可信赖的 agentic 系统"——这对 AI coding agent 赛道整体的产品定位都有参考价值。

**开源阵营的 OpenCode 超过 Claude Code 的 GitHub star 数，折射出一个持续存在的分裂态势**：企业采购者认可 Claude Code 的端到端垂直整合（定价可预测、审计友好、与 Anthropic 深度绑定），而个人开发者和开源爱好者则被 OpenCode 的模型无关性（支持 75+ 模型）和社区开放度吸引。Star 数差距将继续扩大，但两者正在服务日益分化的用户群，直接竞争的意义有限。真正值得关注的，是 OpenCode 的 Scout subagent 和 auto-compact 能力——这些功能在自主研究与长上下文管理上与 Claude Code Dynamic Workflows 构成了不同路径的并行演进。
