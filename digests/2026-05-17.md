## 产品更新 (Product Updates)

- **[v2.1.139 - Agent View 研究预览 / /goal 命令 / 后台会话 - 2026-05-12]** 本周最重磅更新。三项功能同步亮相：

  - **Agent View（研究预览）**：首个面向多会话管理的统一仪表盘，以单一列表展示所有 Claude Code 会话（运行中、等待输入、已完成），支持实时状态刷新。从任意会话按左方向键，或在终端执行 `claude agents`，即可进入 Agent View。目前对 Pro、Max、Team、Enterprise 及 API 计划用户开放。([Anthropic 博客](https://claude.com/blog/agent-view-in-claude-code), [官方文档](https://code.claude.com/docs/en/agent-view), [ClaudeWorld 详解](https://claude-world.com/articles/claude-code-21139-release/))

  - **`/goal` 命令**：基于结果导向的新型任务执行机制。开发者定义完成条件后，Claude 在后台持续工作直到目标达成，全程自动追踪已用时间、轮次与 Token 消耗。支持交互模式、`-p` 模式及 Remote Control 模式。结合 Agent View，`/goal` 成为派发长时任务的核心工具。([Geeky Gadgets 介绍](https://www.geeky-gadgets.com/claude-code-agent-view-update/), [explainx.ai 分析](https://explainx.ai/blog/anthropic-claude-code-agent-view-goal-command))

  - **后台会话（Background Sessions）**：`/bg` 命令可将当前会话转为后台模式；`claude --bg [任务]` 可直接在无终端环境下创建新后台会话。后台会话是完整的 Claude Code 对话，可随时唤醒回复后再次挂起，与 Agent View + `/goal` 形成多 Agent 编排闭环。([MindStudio 教程](https://www.mindstudio.ai/blog/claude-code-bg-command-background-agent-sessions), [HN 讨论](https://news.ycombinator.com/item?id=48124057))

- **[Opus 4.7 Fast Mode 正式默认 - 2026-05-13/14]** Anthropic 于 5 月 13 日正式将 Fast Mode 扩展至 Claude Opus 4.7，5 月 14 日起 `/fast` 命令自动默认使用 Opus 4.7（此前为 Opus 4.6）。Fast Mode 在 Opus 4.7 上可实现最高 2.5 倍的输出速度提升，适合对延迟敏感的场景；定价为 $30/M 输入 + $150/M 输出（标准 Opus 4.7 的 6 倍）。如需固定使用 Opus 4.6，可设置 `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1`。需要 v2.1.139 或更高版本。([ClaudeDevs 公告推文](https://x.com/ClaudeDevs/status/2054266327771275435), [Fast Mode 文档](https://code.claude.com/docs/en/fast-mode), [速度对比评测](https://www.buildfastwithai.com/blogs/claude-opus-4-7-fast-mode-guide))

## 实用技巧 (Tips & Tricks)

- **用 `/goal` 派发无人值守任务**：设置明确的完成条件（如"所有测试通过且 lint 零错误"），配合 `/bg` 将会话移入后台，在 Agent View 中周期性检查进度。适合耗时的重构、批量文档生成或长跑测试等场景，无需保持终端连接。([Agent View 文档](https://code.claude.com/docs/en/agent-view))

- **`claude agents --model --effort` 隔离高消耗任务**：v2.1.142 起可为每个派发的后台会话单独指定模型（如 `--model claude-opus-4-7`）和努力级别（`--effort high`），避免后台任务与前台工作共享算力配额，实现成本与性能的精细化控制。([GitHub Release v2.1.142](https://github.com/anthropics/claude-code/releases/tag/v2.1.142))

- **CLAUDE.md 黄金尺寸：80–120 行**：Claude Code 系统提示占用约 50 条指令槽，模型可稳定遵循约 150–200 条独立指令，因此 CLAUDE.md 实际可用槽位约为 100–150 条。保持在 80–120 行可确保每条规则都被有效权重，超出后规则遵循率会下降。用 `/memory` 命令定期审查是否有冗余条目。([Bijit Ghosh 完整指南](https://medium.com/@bijit211987/the-complete-guide-to-claude-md-memory-rules-loading-and-cross-tool-compression-97cc12ed037b))

- **Plan Mode 架构评审**：Shift+Tab 连按两次激活 Plan Mode（"架构师模式"）。在此模式下 Claude 只观察与分析，不修改任何文件，适合在动手实现前进行影响面评估与方案对比。([shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice))

- **`terminalSequence` 钩子发桌面通知**：v2.1.141 引入的 `terminalSequence` 字段允许钩子在 JSON 输出中附带终端序列，可利用 iTerm2 / WezTerm 等终端的通知 API，在长任务完成时自动弹出系统通知，无需盯着终端轮询。([GitHub Release v2.1.141](https://github.com/anthropics/claude-code/releases/tag/v2.1.141))
