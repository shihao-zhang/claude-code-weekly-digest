## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.139 - Agent View / /goal / 后台会话 - 2026-05-12]** 本周最重磅更新，三项功能同步亮相：

  - **Agent View（研究预览）**：首个面向多会话管理的统一仪表盘，以单一列表展示所有 Claude Code 会话（运行中、等待输入、已完成），支持实时状态刷新。从任意会话按左方向键，或在终端执行 `claude agents`，即可进入 Agent View。目前对 Pro、Max、Team、Enterprise 及 API 计划用户开放。([Anthropic 博客](https://claude.com/blog/agent-view-in-claude-code), [官方文档](https://code.claude.com/docs/en/agent-view))

  - **`/goal` 命令**：基于结果导向的新型任务执行机制。开发者定义完成条件后，Claude 在后台持续工作直到目标达成，全程自动追踪已用时间、轮次与 Token 消耗。支持交互模式、`-p` 模式及 Remote Control 模式。([Geeky Gadgets 介绍](https://www.geeky-gadgets.com/claude-code-agent-view-update/))

  - **后台会话（Background Sessions）**：`/bg` 命令可将当前会话转为后台模式；`claude --bg [任务]` 可直接在无终端环境下创建新后台会话，与 Agent View + `/goal` 形成多 Agent 编排闭环。([MindStudio 教程](https://www.mindstudio.ai/blog/claude-code-bg-command-background-agent-sessions))

- **[Opus 4.7 Fast Mode 正式默认 - 2026-05-13/14]** Anthropic 于 5 月 13 日正式将 Fast Mode 扩展至 Claude Opus 4.7，5 月 14 日起 `/fast` 命令自动默认使用 Opus 4.7（此前为 Opus 4.6）。Fast Mode 在 Opus 4.7 上可实现最高 2.5 倍的输出速度提升；定价为 $30/M 输入 + $150/M 输出（标准 Opus 4.7 的 6 倍）。如需固定使用 Opus 4.6，可设置 `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1`。([Fast Mode 文档](https://code.claude.com/docs/en/fast-mode))

- **[v2.1.140 - 2026-05-14]** 修复 Agent 工具 `subagent_type` 匹配问题（现在对大小写与分隔符不敏感）；更新 Agent 颜色方案；修复多项内部 claim-verify 逻辑漏洞。([GitHub Release v2.1.140](https://github.com/anthropics/claude-code/releases/tag/v2.1.140))

- **[v2.1.141 - 2026-05-14]** 新增 `terminalSequence` 字段到钩子 JSON 输出，支持桌面通知等终端序列集成；新增 `ANTHROPIC_WORKSPACE_ID` 环境变量，用于工作负载身份联合（Workload Identity Federation）认证；扩展 `claude agents` 子命令选项。([GitHub Release v2.1.141](https://github.com/anthropics/claude-code/releases/tag/v2.1.141))

- **[v2.1.142 - 2026-05-15]** 为 `claude agents` 命令新增以下标志，支持对派发的后台会话进行细粒度配置：`--add-dir`、`--settings`、`--mcp-config`、`--plugin-dir`、`--permission-mode`、`--model`、`--effort`、`--dangerously-skip-permissions`，大幅提升多 Agent 场景下的会话隔离与权限控制能力。([GitHub Release v2.1.142](https://github.com/anthropics/claude-code/releases/tag/v2.1.142))

- **[v2.1.143 - 2026-05-15]** 插件依赖管理增强：`claude plugin disable` 在被依赖时拒绝操作并给出可一键粘贴的完整禁用链命令；`claude plugin enable` 自动强制启用传递依赖；`/plugin` 市场浏览面板新增每次调用的预估 Token 成本展示。新增 `worktree.bgIsolation: "none"` 配置项，让后台会话直接编辑工作区副本而无需创建 worktree。([GitHub Release v2.1.143](https://github.com/anthropics/claude-code/releases/tag/v2.1.143))

## 实用技巧 (Tips & Tricks)

- **用 `/goal` 派发无人值守任务（Claude Code）**：设置明确的完成条件（如"所有测试通过且 lint 零错误"），配合 `/bg` 将会话移入后台，在 Agent View 中周期性检查进度。适合耗时的重构、批量文档生成或长跑测试等场景，无需保持终端连接。([Agent View 文档](https://code.claude.com/docs/en/agent-view))

- **`claude agents --model --effort` 隔离高消耗任务（Claude Code）**：v2.1.142 起可为每个派发的后台会话单独指定模型和努力级别，避免后台任务与前台工作共享算力配额，实现成本与性能的精细化控制。([GitHub Release v2.1.142](https://github.com/anthropics/claude-code/releases/tag/v2.1.142))

- **`terminalSequence` 钩子发桌面通知（Claude Code）**：v2.1.141 引入的 `terminalSequence` 字段允许钩子在 JSON 输出中附带终端序列，可利用 iTerm2 / WezTerm 等终端的通知 API，在长任务完成时自动弹出系统通知，无需盯着终端轮询。([GitHub Release v2.1.141](https://github.com/anthropics/claude-code/releases/tag/v2.1.141))

- **Codex CLI 提前使用 `codex doctor`（Codex CLI）**：v0.131.0-alpha 中的 `codex doctor` 可在出现问题前主动生成一份涵盖 runtime/auth/terminal/network/config 的健康报告，是调试环境问题或向 OpenAI 提交 Bug 报告的标准工具。([X/@CodexReleases](https://x.com/CodexReleases/status/2056431344604025041))

- **Gemini CLI Auto Memory Inbox（Gemini CLI）**：v0.42.0 的 Auto Memory Inbox 支持 AI 自动维护跨会话记忆，开发者可设置记忆策略（保留/删除/合并条目），让 CLI 随使用时间积累项目上下文，减少每次会话的"冷启动"成本。([Gemini CLI Changelog](https://geminicli.com/docs/changelogs/))

## 横向洞察 (Cross-cutting Insights)

本周最值得记录的事件是 **Roo Code 正式关停**。一个拥有 300 万次安装量的主流 IDE 扩展，选择在 2026 年 5 月放弃 IDE 内嵌路线，转向完全云化的 agent 形态（Roomote）。这是一个强烈的行业信号：**IDE 扩展模式的天花板开始显现**，而"无需开发者在场、在云端独立完成任务"的 cloud agent 模式正在被更多创业团队视为下一个阶段的终局形态。

与此同时，Claude Code 的 Agent View + `/goal` + 后台会话，Codex CLI 的 `/goals` 持久化工作流，Windsurf 的 Spaces + Devin Cloud，Gemini CLI 的 Auto Memory Inbox——**四大工具在本周不约而同地强化了"任务的持久化与跨会话延续"能力**。不再是单次对话，而是可以暂停、恢复、在后台持续运转的长期工作流。这是 AI coding agent 从"工具"向"同事"演进的关键特征收敛。

**Gemini CLI 的 Auto Memory Inbox 是本周技术上最有差异化的功能**。其他工具的跨会话记忆主要依赖用户手动管理 CLAUDE.md 或 `.aider` 配置文件，而 Gemini CLI 将记忆的维护和更新自动化，且有规范化的补丁协议。这与 Claude Code 前两周演示的 "Dreaming" 记忆巩固机制在概念上高度相似——跨会话 agent 记忆正在成为下半年的核心战场。
