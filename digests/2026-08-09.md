## Claude Code 产品更新 (Claude Code Updates)

- **[自托管环境（Self-hosted environments）公测 - 2026-08-06]** 本周 Claude Code 最重要的发布，把云端会话的执行位置交还给客户：
  - 组织在 claude.ai 管理后台创建**命名环境（named environments）**，每个环境下挂一组 **runner** —— 部署在自家网络内的长驻进程，工作方式与自托管 CI runner 完全一致
  - 支持**固定 runner 与按需 runner 两种模式**：可以自己起好长跑，也可以运行 autoscaling orchestrator，让 runner 随会话排队而启动、任务结束后自行退出
  - 从 web / 移动端 / 桌面端 / routine 发起的会话都在你的网络里跑，紧挨着内部服务、工具链和安全管控运行，而不是跑在 Anthropic 的基础设施上
  - **仓库检出、构建产物、密钥以及会话创建或修改的任何文件都留在组织自己配置的机器上**
  - 面向 **Claude Team / Enterprise 计划**公测，**默认关闭**，且**不支持启用了 ZDR 的组织**
  - Anthropic 自己的建议很克制：多数企业仍应优先用托管版本（运维更简单），自托管是给网络、工具链或合规要求必须把 Agent 执行留在自有基础设施上的团队

  ([Anthropic Blog](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute), [官方文档](https://code.claude.com/docs/en/self-hosted-environments), [Unite.AI](https://www.unite.ai/claude-code-sessions-can-now-run-on-infrastructure-your-team-controls/))

## 实用技巧 (Tips & Tricks)

- **`Ctrl+Alt+F` 折叠工具刷屏（Claude Code v2.1.221）**：Focus 视图把工具活动收成可展开的摘要。跑长任务时终端不再被 tool call 洪水淹没，而需要复盘某一步时再展开即可——比事后翻 transcript 高效得多。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **用 `--approve-for-me` 治「审批疲劳」（Codex CLI v0.147.0）**：这个新标志把符合条件的审批交给一个独立的 reviewer 子 Agent 在 workspace-write 沙盒下判断，只把真正有风险的操作升级给你。注意它是**降低打断频率**而非取消审批——本质是拿一个 LLM 当第一道过滤，跟 `--dangerously-skip-permissions` 是两回事。([GitHub Release v0.147.0](https://github.com/openai/codex/releases/tag/rust-v0.147.0))

- **自托管 runner 先从「按需」起步（Claude Code v2.1.224）**：`claude self-hosted-runner` 支持固定长驻和 autoscaling orchestrator 两种模式。首次接入建议直接用按需模式——runner 随会话排队启动、任务结束自行退出，不必先为峰值容量做规划；跑顺了再把高频环境切成固定 runner 省启动延迟。([官方文档](https://code.claude.com/docs/en/self-hosted-environments))

- **用 owner 通配符批量管住插件来源（Claude Code v2.1.223）**：marketplace 条目现在支持 owner 级通配符，可以一条规则 allowlist / blocklist 整个组织的仓库。对企业管理员来说，这比逐个仓库维护名单现实得多——配合 v2.1.224 的「HTTPS 归档包安装 + SHA-256 校验」，插件供应链才算有了两道锁。([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))

- **迁移到 Codex 时别重复导入（Codex CLI v0.147.0）**：新版本支持导入 Cursor 托管的 skills，并且对已导入的 Claude / Cursor 会话做增量同步而**不产生重复条目**。此前反复 `/import` 会堆出一堆同名副本，现在可以把导入当成常态化同步而非一次性搬家。([GitHub Release v0.147.0](https://github.com/openai/codex/releases/tag/rust-v0.147.0))

- **先查 NDA 再开 Contributor 档（Meta Muse Code）**：便宜 21 倍很诱人，但流经终端 Agent 的不只是代码，还有架构、客户名、密钥使用方式和提交历史。实操建议：开源仓库、一次性原型、公开文档走 Contributor；专有代码库走标准档；如果你的服务协议写于 2024 年之前，先确认「第三方披露」条款是否覆盖模型训练这种用法。([The New Stack](https://thenewstack.io/meta-muse-code/), [Codersera](https://codersera.com/blog/muse-code-contributor-tier-privacy-2026/))

## 横向洞察 (Cross-cutting Insights)

**Meta 下场，把这条赛道的定价底线一次性拉穿。** 8/5 的 Muse Code 是本周最大的结构性变量，但真正值得注意的不是 82.9% 的 Terminal-Bench 分数（该分数尚未进官方 verified 榜单，且仍落后 Claude Opus 5 的 86.7%），而是它的定价表：Contributor 档输出 $0.20/MTok，比标准档便宜约 21 倍，代价是拿你的 prompt 和 completion 训模型。上周 OpenAI 把 GPT-5.6 Luna 降价 80% 时，我们判断竞争维度正从「模型能力」切到「单位任务成本」；Meta 这一手把这个趋势推到了逻辑终点——**成本可以降到接近零，只要你愿意把代码本身当成对价**。这是 Meta 一贯的打法（用开放/低价换数据与生态位），但放在终端编程 Agent 这个场景里格外锋利：流经 Agent 的不是搜索词，是架构、客户名和提交历史。社区的反应也很成熟，没有停留在「便宜真香」，而是直接跳到了 2024 年前写的 NDA 是否覆盖模型训练这种用法上。当一款工具的定价页需要法务参与评审时，它就已经不只是工具选型了。

**Claude Code 与 Codex 在同一周里，分别给出了「信任边界该画在哪」的两个不同答案。** Anthropic 的答案是**把执行搬回你的机房**：自托管环境让仓库检出、构建产物、密钥和一切会话产出物都留在客户自己配置的机器上，runner 的形态刻意做成了自托管 CI runner——一个企业运维已经完全理解的心智模型。OpenAI 的答案则是**在原地把审批自动化**：`--approve-for-me` 派一个独立的 reviewer 子 Agent 去过滤审批请求，只把真正危险的升级给人。两者解决的是同一个痛点的两端——前者降低「数据去哪了」的焦虑，后者降低「我要点多少次同意」的疲劳。有意思的是双方在另一半又高度趋同：Claude Code 本周四个版本连续修补权限绕过（zsh 正则条件式、填充式命令、PreToolUse hook 自动放行、沙盒 deny-list 绕过、`bypassPermissions` 缺口），Codex v0.147.0 同步上了密钥与 bearer token 脱敏、插件隔离网络拒绝、凭据使用前的项目信任校验。在 OWASP 追踪的 53 个 agentic 项目里有 28 个是编程 Agent、prompt injection 同比涨 340% 的背景下，**权限系统的补丁密度已经成为这类产品最诚实的成熟度指标**——它不好看，但它是唯一无法用 demo 伪装的东西。

**「多 Agent 记忆」正在从社区补丁变成产品内建能力，这是下一个能力聚合点。** 本周有两条看似无关的线索指向同一处：官方侧，Claude Code v2.1.224 上了跨会话消息（且专门配了权限绕过防护）；社区侧，Memmy 这类跨 Agent 记忆中枢在快速冒头，claude-mem 已经把插件铺到了六款工具上。社区对问题的表述比厂商更直白——多 Agent 工作流的瓶颈不是推理能力，是**集体失忆加上 Agent 之间零通信**。Meta 的持久化异步后台 Agent（常驻而非按任务 spawn，以避免重复信息收集）和可重放事件日志，其实是同一个问题的第三种解法：既然记忆难共享，那就别让 Agent 死掉。三条路径的共同前提是，单会话、单 Agent 的抽象已经不够用了。可以合理预期：**会话间的状态与消息传递，会像 MCP 之于工具调用那样，在未来两三个季度里长出一层标准**——现在各家各造各的，正是标准出现前的典型形态。
