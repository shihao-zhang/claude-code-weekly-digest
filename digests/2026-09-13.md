## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.269 - `claude plugin eval`：插件生态第一次有了可复现的评分 - 2026-09-11]** 本周 Claude Code 最值得单独拎出来的功能，全版共 **98 项 CLI 变更**：
  - 新增 **`claude plugin eval`**：把插件自带的 eval 套件跑在 Claude Code 上，产出**打分过的、可复现的结果（JSON + HTML 报告）**。官方文档同步上线 `plugin-evals` 页与 `claude plugin eval` / `claude plugin eval init` 命令参考——插件作者从此有了一条明确路径去度量「我的插件到底改变了 Claude 的行为没有」，并可以拿它当发版门禁
  - 新增 **`/output-style [name]`** 列出并切换输出风格（覆盖 Remote Control 与云端 / headless 会话）
  - **Bash 工具结果里开始带「这条命令改了哪些文件」的 diff**（Bash 工具承接文件编辑时）
  - 新增 **`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1–256）**，用于抬高 Workflow 扇出的并发 Agent 上限；新增 `OTEL_METRICS_INCLUDE_REPOSITORY`、`CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS`
  - **VS Code 侧这版给得很足**：**Agent map**（列出会话全部子 Agent，每个一张卡片 + 只读 transcript）、**Hooks 管理对话框**（user / project / local 三层设置）、**权限规则对话框**、运行中子 Agent 的实时进度行
  - 修复：**响应被截断后自动续跑会部分作废 prompt 缓存**、会话中途换模型导致该回合回复丢失、`/goal` 遇 API 错误后静默卡死（改为退避重试或明确暂停）、经托管设置启用的组织插件在 headless 与桌面端不加载
  - Claude Code on the web：**可在 Claude 读到之前撤回排队中的消息**

  ([v2.1.269](https://github.com/anthropics/claude-code/releases/tag/v2.1.269), [官方 changelog](https://code.claude.com/docs/en/changelog), [Claude Code Changelog on X](https://x.com/ClaudeCodeLog/status/2098496228455530979))

  - **修复 WebFetch 无限挂起**：现在 300 秒后失败，可用 `CLAUDE_CODE_WEBFETCH_DEADLINE_MS` 调整
  - 修复**符号链接目录上的 deny / ask 规则不生效**（上期刚集中修过一轮软链接逃逸，这条是同一簇的续集）；修复**插件 / MCP 报错里带出 token 与密码**
  - 修复**长会话持续高 CPU**；修复另一进程刷新陈旧的模型访问记录时，会话**静默切回组织默认模型**

  - 其余：Cowork 定时任务在要求沙箱的组织下启动即失败、`/context` 与本地命令在移动端渲染空白、过期的 AWS / Google Cloud 凭据要重试 10 次才提示重新认证

## Codex CLI 产品更新 (Codex CLI Updates)

- **[Agents API 公测：Codex 的 harness 本身成了托管服务 - 2026-09-10]** 本周赛道最大的结构性新闻：
  - OpenAI 把**驱动 Codex 的那套 harness 与执行基础设施**直接开成 API。开发者不必再自建编排层、上下文管理层与沙箱层：**长时会话、并行工具调用、子 Agent 委派、上下文自动压缩**全部由 OpenAI 托管——会话逼近上限时 API 自动压缩早期上下文，**开发者不用再写自己的 compaction 逻辑**
  - 执行环境三选一：**OpenAI 托管沙箱、自己 VPC 内自托管、或 9 家合作方沙箱**（Blaxel、Cloudflare、Daytona、DigitalOcean、E2B、Modal、Oracle、Runloop、Vercel）
  - **定价：Agents API 本身不额外收费**，只按底层模型与工具用量计费，托管沙箱按容器费率
  - **公测期的两条硬限制值得记下**：**数据驻留仅限美国**，且**不支持 Zero Data Retention**——选自托管沙箱**也不会**让它变成 ZDR 合规

  ([OpenAI 官方](https://openai.com/index/introducing-the-agents-api/), [MarkTechPost 技术拆解](https://www.marktechpost.com/2026/09/10/openai-launches-the-agents-api-in-public-beta-putting-the-codex-harness-behind-one-api-call/), [The Decoder](https://the-decoder.com/openais-new-agents-api-gives-developers-the-infrastructure-behind-codex-and-chatgpt/), [OpenAI Developers on X](https://x.com/OpenAIDevs/status/2098130570048045453), [AiCybr 定价与沙箱细节](https://aicybr.com/blog/openai-agents-api-codex-harness-hosted-sandboxes))

  - **GPT-6 Astra 进入模型选择器与 Amazon Bedrock 目录**——上期它只是「内置默认」，这版才真正在 UI 里可选可切
  - **实验性 worktree 支持（`--worktree` 或 `/worktree`）**：为新会话或 fork 出来的会话**创建隔离 checkout**，之后可浏览与恢复。这是 Codex 第一次把「多会话并行改同一个仓库」的隔离问题放进 CLI 本体
  - **内联回答问题**：Codex 提问时可以**用建议选项或自定义文本就地回答，而 Codex 继续干活、你的主草稿不丢**
  - **Windows 会话可共享一个后台 Codex server**，配套 daemon 生命周期命令与托管更新
  - Vim 编辑新增 **`R` 替换模式**（含撤销与 `.` 重复），旧终端下 Escape 处理更可靠；复制回复保留富文本格式，`/copy` 支持状态输出
  - 修复：会话能感知新装的插件工具并在外部升级后刷新、MCP OAuth token 刷新与登录挑战协调、**信任建立之前不再运行工作区 helper**、远程操作保留已保存权限、**授权 review 穿越压缩存活且拒绝陈旧批准**

## 实用技巧 (Tips & Tricks)

- **用第三方 Anthropic 兼容端点的，立刻确认版本。** **2.1.265 到 2.1.267 之间，第三方端点上的每一个回合都会 HTTP 400**（根因是 Artifact 工具输入 schema 的一个正则），2.1.268 才修。如果你这周「突然全挂」，不用查自己的网关配置，升到 2.1.268+ 即可。（Claude Code，[v2.1.268](https://github.com/anthropics/claude-code/releases/tag/v2.1.268)）

- **用 `CLAUDE_CODE_USE_GATEWAY` + API key / `apiKeyHelper` / 自定义认证头的，跳过 2.1.265。** 那一版里该环境变量**单独存在就会强制走 Cloud gateway 登录**，把这类组合配置全部打断；2.1.266 当天就把它改回「单独出现时忽略」。（Claude Code，[v2.1.266](https://github.com/anthropics/claude-code/releases/tag/v2.1.266)）

- **要给团队的努力等级封顶，用 `maxEffortLevel`。** 可全局设也可按模型设，**在 Bedrock / Vertex / Foundry 上都生效**，且用户仍能自行往下选。比起事后看账单，这是本周唯一一个「事前就能压住成本」的新旋钮。（Claude Code，[v2.1.267](https://github.com/anthropics/claude-code/releases/tag/v2.1.267)）

- **写插件的，把 `claude plugin eval` 接进发版流程。** 它跑插件自带的 eval 套件并产出 **JSON + HTML 的可复现评分**，可以直接当门禁用——发版前对比「有插件 / 无插件」的行为差异，而不是靠手感。（Claude Code，[v2.1.269](https://github.com/anthropics/claude-code/releases/tag/v2.1.269)）

- **托管了 `allowedHttpHookUrls` / `httpHookAllowedEnvVars` / `allowedChannelPlugins` 的管理员，本周必须升级。** 2.1.267 之前，**这些托管清单在文件不可读时是「放行一切」**，等于策略在最需要生效的时候失效。现在改为 fail-closed。（Claude Code，[v2.1.267](https://github.com/anthropics/claude-code/releases/tag/v2.1.267)）

- **靠 deny / ask 规则挡目录的，检查有没有符号链接。** v2.1.268 修复了**软链接目录上的 deny / ask 规则不生效**。这已经是连续第三周出现同一簇问题（上期是文件工具与 Grep/Glob 的路径逃逸）——**把软链接当成权限规则的已知弱面来对待，别当成偶发 bug**。（Claude Code，[v2.1.268](https://github.com/anthropics/claude-code/releases/tag/v2.1.268)）

- **一次装一堆插件：`--plugin-dir` 现在可以直接指向文件夹。** 文件夹下每个带 manifest 的子目录都会被加载，适合把团队内部插件放在一个目录里统一分发，不必逐个注册。（Claude Code，[v2.1.265](https://github.com/anthropics/claude-code/releases/tag/v2.1.265)）

- **Workflow 扇出嫌慢的，调 `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1–256）。** 默认并发上限本周开放成了可配置项。配合 v2.1.269 的 VS Code **Agent map**（每个子 Agent 一张卡片 + 只读 transcript），大扇出终于有了对应的观测面。（Claude Code，[v2.1.269](https://github.com/anthropics/claude-code/releases/tag/v2.1.269)）

- **Codex 多会话改同一个仓库的，试试 `--worktree` / `/worktree`。** 它为新会话或 fork 会话**创建隔离的 checkout**，之后可浏览与恢复——比手工 `git worktree add` 再切目录省事，也从根上避免并行会话互相踩工作区。实验性。（Codex CLI，[v0.154.0](https://github.com/openai/codex/releases/tag/rust-v0.154.0)）

- **Codex 提问打断你写草稿的，这版修了。** 现在可以**内联回答（用建议选项或自定义文本），Codex 继续干活，你的主草稿不丢**。长任务里这条比听起来更值钱。（Codex CLI，[v0.154.0](https://github.com/openai/codex/releases/tag/rust-v0.154.0)）

- **脚本里还在调 `codex mcp-server` 的，本周会断。** 这个废弃已久的入口在 v0.154.0 被移除了。（Codex CLI，[v0.154.0](https://github.com/openai/codex/releases/tag/rust-v0.154.0)）

## 横向洞察 (Cross-cutting Insights)

**这一周的主线是：harness 从「产品的护城河」变成了「可以被别人买走的一层」。** 上期我们写过，模型差距在收窄、harness 差距在放大——那句话这周被 OpenAI 用一个 API 直接兑现，方向却和预期相反。**Agents API 把驱动 Codex 的编排、长时会话、上下文自动压缩、子 Agent 委派、沙箱执行整体开放，而且不额外收费**，只按模型与工具用量计价，沙箱还给了 OpenAI 托管 / 自托管 VPC / 九家合作方三条路。这不是一个功能发布，是一次**定价结构上的降维**：过去十二个月里，每一个 CLI Agent 项目最难的工程量恰好就是这几块，现在它们变成了一次 API 调用。**下游工具从此只有两种活法**——接进去、把精力挪到上层体验，或者拿出足够具体的理由说明自己的 harness 为什么值得单独维护。有意思的是同一周 Anthropic 的动作正好在另一侧：`claude plugin eval` 给的不是能力，而是**一把尺**——插件作者可以用可复现的评分证明自己的扩展确实改变了行为。**一边把底座变成公共品，一边把上层变成可度量的市场**，两家都在往「harness 不再是秘密」的世界里走，只是入口不同。

**第二条线：协调者—执行者的分层，本周同时出现在三家的产品形态里，而且长得越来越像。** Cursor 的 Projects 把它做得最直白——**一个不写代码的协调者 Agent**，负责规划、分派、收回验收，跑在云端自己的机器上，合上笔记本不停，还能盯 Slack 频道、按计划表跑、跟住所有 PR 并主动行动。OpenAI 的 Agents API 把同一套东西做成了 API 原语（子 Agent 委派 + 长时会话 + 自动压缩）。Claude Code 这周给的则是这套形态**缺失的观测面与刹车**：`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 把扇出上限交给用户（1–256），VS Code 的 **Agent map** 给每个子 Agent 一张卡片和只读 transcript，`maxEffortLevel` 在所有 provider 上给努力等级封顶。**三家在同一周分别给出了这套架构的「执行层」「编排层」和「治理层」**，而它们合起来描述的是同一个东西：人类从「每个任务开一个对话」退到「和一个协调者对话」，再退到「看一张 Agent 地图」。**值得注意的是治理工具的出现比能力晚了整整一个季度**——先有并行扇出，四个月后才有并发上限和努力等级上限。

**第三条线：这一周把「能力越强、被借用的杠杆越大」写成了案例，而不是风险提示。** Anthropic 的威胁情报报告里最硬的一条是：**一个疑似国家背景的组织操纵 Claude Code 对约 30 个全球目标发起入侵尝试并在少数目标得手，官方认为这是首个有记录的、无实质人工介入的大规模网络攻击**。请把它和上期那条放在一起读——OpenAI 用 Preparedness「Critical」门槛把 Astra 的网络安全能力锁进 Daybreak 申请制，并提前承认普通用户会在无关工作里被误伤；Anthropic 则把误拦截降了 60%、另开 Mythos 5.1 受审核通道，这周再把已发生的滥用摊开。**两条路径的分歧不在于谁更负责，而在于风险在哪一端被计价：OpenAI 计在事前的准入，Anthropic 计在事后的披露。** 而同一周的工程细节给了这个宏观分歧一个非常具体的注脚：Claude Code 修掉了「托管的 hook URL 白名单在文件不可读时放行一切」，以及「符号链接目录上的 deny / ask 规则不生效」——**两条都是「策略写了但在关键时刻不生效」型的静默故障，也是连续第三周出现的同一簇问题**。宏大的准入框架和一行 fail-closed 的修复，在真实攻防里的权重可能是反过来的。
