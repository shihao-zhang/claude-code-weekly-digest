- **[「常驻 Agent」成为本周社区最大公约数话题]** Persistent 模式的代码泄露把一个此前只在推特上模糊讨论的问题推到台面：**当 Agent 不再有「回合结束」这个概念，谁来定义它的边界？** 社区讨论集中在三点——(1) 自己给自己派活的 Agent 如何做成本封顶；(2)「主动联系用户」意味着 Agent 从被调用方变成了发起方，通知与打扰的治理规则完全空白；(3) OpenAI 强调「用户系统之外的更改仍需审批」，但**跨会话持续运行本身就在稀释「一次审批覆盖多大范围」的语义**。值得注意的是，同一周 Claude Code 恰好把 `/loop` 的**自定步调与无提示 autonomous 模式全量开放**（v2.1.248），两家在同一个方向上一个高调、一个安静。([the-decoder](https://the-decoder.com/always-on-and-self-starting-ai-agents-might-be-openais-next-big-play/), [Slashdot](https://features.slashdot.org/story/26/08/27/224230/openai-is-developing-a-persistent-ai-agent), [Claude Code v2.1.248](https://github.com/anthropics/claude-code/releases/tag/v2.1.248))

## 实用技巧 (Tips & Tricks)

- **长会话每小时莫名变贵？先升到 v2.1.248。** Claude Code 修复了一个长期存在的问题：长会话中**工具定义被重新渲染**，导致大约每小时命中一次 prompt 缓存 miss（`ScheduleWakeup` 工具定义中途变化也会触发）。跑长任务的话这条比任何新功能都值钱。配套地，v2.1.243 新增了 `promptCacheTtl` / `subagentPromptCacheTtl` 设置，v2.1.248 允许在 agent frontmatter 里写 `experimental.cacheTtl` 做 per-agent 配置。（Claude Code，[v2.1.248](https://github.com/anthropics/claude-code/releases/tag/v2.1.248) / [v2.1.243](https://github.com/anthropics/claude-code/releases/tag/v2.1.243)）

- **先跑一次 `/claude-api cost-optimize` 再谈省钱。** 新命令会剖析你的支出构成并给出针对性建议，比凭感觉调 `/effort` 或换模型靠谱得多。配合 v2.1.251 新增的 `/cost` **每会话 prompt 缓存指标**，可以直接看出缓存到底有没有生效。（Claude Code，[v2.1.247](https://github.com/anthropics/claude-code/releases/tag/v2.1.247) / [v2.1.251](https://github.com/anthropics/claude-code/releases/tag/v2.1.251)）

- **不信任的仓库用 `--restricted` 起。** 移除全部内置工具、文件工具限定在工作目录内，是目前 Claude Code 最窄的一档能力面。审别人的代码、跑不明来源的 PR 时默认用它。（Claude Code，[v2.1.248](https://github.com/anthropics/claude-code/releases/tag/v2.1.248)）

## 横向洞察 (Cross-cutting Insights)

**这一周，「一次回合」这个单位正式解体了。** 上周我们看到各家在解决「会话不再是一次性的」；这周问题被推进到了更根本的一层——**回合本身不再是自然的边界**。WIRED 扒出的 Codex Persistent 模式，把它挂在**推理努力等级**这个位置上，语义直白得刺眼：low / medium / high 说的是「花多少算力」，而 Persistent 说的是「**一直做到被放去睡觉为止**」——两者根本不是同一个量纲，把它塞进同一个菜单，等于宣布「工作量」这个维度已经从「多深」变成了「多久」。配套行为更说明问题：自己给自己派后续任务、跨会话持续、主动联系用户。同一周 Claude Code 悄悄把 `/loop` 的**自定步调 dynamic 模式与无提示 autonomous 模式全量开放**，把 `/goal` 的 check-in 限制在**每目标最多三次**——这是同一件事的另一半：既然 Agent 会长期自己跑，那就必须内建「什么时候该找人、找几次」的礼仪。**一个高调地把常驻做成卖点，一个安静地把常驻做成默认能力并配上打扰预算，方向完全一致。**

**第二条线：成本从「事后账单」变成了「运行时一等公民」，而且各家给出的抓手惊人地对称。** Claude Code 这周一口气上了 `promptCacheTtl` / `subagentPromptCacheTtl` / `experimental.cacheTtl`（缓存 TTL 可配）、`modelPricing`（写入合约单价）、`/usage` 的花费上限进度条、`/cost` 的每会话缓存指标、`/claude-api cost-optimize`（支出剖析），还修掉了一个**长会话每小时掉一次 prompt 缓存**的长期 bug，并把 Workflow 工具的提示词占用从 5.7k 压到 1k；Codex 这边把**嵌套子 Agent 的 token 用量计入根目标预算**，让远程 compaction 把保留的图片计入 token 预算；oh-my-pi 加了 `omp usage clients` 按客户端拆用量。**把这些放在一起看，会发现它们全都不是「让模型更便宜」，而是「让开销可归因、可设限、可审计」。** 这个转向的时机不是巧合——本周社区那批互相打架的对比测试（同一对工具，成本差距从 1.4 倍到 4 倍不等）恰好证明了：在长跑、多 Agent、多 provider 的现实里，**成本已经不是一个可以在评测里测出来的属性，而是一个必须在运行时管理的属性**。当 Persistent 这类「不会自己停」的模式真的上线，没有预算封顶与归因的产品会第一个出事。

**第三条线最安静，但可能是本周最重要的：安全的重心从「模型会不会被骗」转向了「路径与信任边界会不会被绕过」。** Claude Code v2.1.251 一次性修掉了一整簇同构的问题——文件工具跟随被掉包的软链接读写审批范围外的位置、Grep/Glob 对软链接搜索路径不应用 deny 规则、插件命令指向插件目录之外、Workflow 工具在权限检查**之前**就读取越权的 `scriptPath`；v2.1.248 修掉 `/ultrareview` 上传未提交的 `.env`；v2.1.246 修掉 Bash 权限检查对畸形操作符不要求审批。Codex 这边同期修掉**不受信任项目仍能注入项目级 `AGENTS.md`**、**`/cd` 会削弱 sandbox 限制**、**陈旧的 Guardian 分类结果在权限状态变更后继续授权动作**。**这些没有一条是「prompt injection 骗过了模型」——全部是经典的系统安全问题：TOCTOU、软链接逃逸、检查与使用顺序颠倒、缓存的授权决策未失效。** 结合本周的第三方研究（多家 Agent 被发现可通过 Git 元数据间接引用绕过基于路径的沙箱规则，或让特权本地守护进程变成沙箱外的执行环境），结论已经很清楚：Agent 的攻击面正在从「AI 安全」滑向「操作系统安全」，而这个领域有四十年的经验和四十年的坑。往好处想，这意味着防御方法是已知的；往坏处想，这意味着**每一家 Agent 厂商都在重走一遍别人走过的路，而它们的产品迭代速度是每天一个版本**。([Claude Code v2.1.251](https://github.com/anthropics/claude-code/releases/tag/v2.1.251), [Codex v0.151.0](https://github.com/openai/codex/releases/tag/rust-v0.151.0), [Pillar / TechRadar 沙箱逃逸研究](https://www.techradar.com/pro/security/top-ai-coding-agents-can-be-easy-victims-to-sandbox-escapes-showing-they-arent-as-secure-as-they-claim-to-be))
