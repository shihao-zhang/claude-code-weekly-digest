## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.178 - Agent Teams 架构重组：隐式团队 + 直接 spawn 队员 - 2026-06-15]** 本周最重要的 Claude Code 架构变更：`TeamCreate` / `TeamDelete` 两个工具被移除，会话现在具有**隐式团队**，无需显式创建团队对象。开发者可直接在 Agent 工具的 `name` 参数中命名队员并 spawn，启用方式：`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`。

  其他重要变更：
  - **`Tool(param:value)` 权限规则语法**：新增按工具输入参数匹配的权限规则，例如 `Agent(model:opus)` 可仅对指定模型的 Agent 调用生效，精细化权限管控
  - **嵌套 `.claude/skills` 目录自动加载**：多层 `.claude/` 目录中的 Skills 现在正确加载，同名冲突时最近的 `.claude/` 目录优先
  - **Auto 模式子 Agent 分类器**：子 Agent spawn 前先经过 classifier 评估，提升自主模式下的运行安全性
  - 修复多个子 Agent 问题：查看转录、消息投递、后台化行为；修复 `--fallback-model` 被压缩流程忽略的问题

  ([Claude Code Changelog](https://code.claude.com/docs/en/changelog), [DevelopersIO v2.1.178 解析](https://dev.classmethod.jp/en/articles/20260616-cc-updates-v2-1-178/))

- **[v2.1.179 - 连接稳定性修复 - 2026-06-16]** 修复流式传输中断时部分响应丢失（现在保留已生成内容，不再显示裸错误）；修复 WSL2 + Windows Terminal / VS Code 环境下的鼠标滚轮失效；修复大目录沙箱 glob 匹配导致会话无法使用；改善远程会话中的插件加载性能。
  ([Claude Code Changelog](https://code.claude.com/docs/en/changelog), [DevelopersIO 解析](https://dev.classmethod.jp/en/articles/20260618-cc-updates-v2-1-181/))

- **[v2.1.181 - /config 命令行设置 + CLAUDE_CLIENT_PRESENCE_FILE + Bun 1.4 - 2026-06-17]** 功能面丰富的一个版本：
  - **`/config key=value` 语法**：可直接在提示框中通过 `/config` 命令行修改设置，适用于交互式、`-p`（print 模式）、Remote Control 三种场景，无需手动编辑配置文件
  - **`CLAUDE_CLIENT_PRESENCE_FILE`**：新环境变量，设置后可抑制移动端推送通知，适合无人值守的后台自动化脚本场景
  - **Bundled Bun 升级至 1.4**：内置 Bun 运行时升级，提升 JS/TS 工具执行性能
  - 改善长段落流式显示（逐行输出）、子 Agent 面板自动隐藏和滚动提示、API 连接中断后的自动重试
  - 修复自定义 `ANTHROPIC_BASE_URL` 和 Foundry 下 prompt 缓存失效；修复 macOS Apple Events 权限问题；修复 `/recap` 切换模型后继续使用旧模型的问题

  ([Claude Code Changelog](https://code.claude.com/docs/en/changelog), [DevelopersIO 解析](https://dev.classmethod.jp/en/articles/20260618-cc-updates-v2-1-181/))

- **[v2.1.183 - Auto 模式安全守卫：阻断未授权的破坏性命令 - 2026-06-19]** 本周最重要的安全增强，直接从 Anthropic Engineering 博客的 auto mode 安全分类器架构延伸而来：

  **Auto 模式现在阻断以下命令（除非用户明确要求）：**
  - `git reset --hard`、`git checkout -- .`、`git clean -fd`、`git stash drop`（未经请求时丢弃本地工作）
  - `git commit --amend`（当此次 commit 不是本次 agent 会话创建的）
  - `terraform destroy`、`pulumi destroy`、`cdk destroy`（未指定目标堆栈时）

  其他改动：
  - **模型弃用警告**：检测到模型即将被自动升级到新版本时，在 stderr（print 模式）和 agent frontmatter 中显示警告
  - **`attribution.sessionUrl` 设置**：可从 commit 和 PR 中省略 claude.ai session 链接（适用于 Web 和 Remote Control 会话）
  - **`/config --help`**：列出所有可用的 shorthand key
  - 修复子 Agent spawn 时 `thinking.disabled.display` 400 错误；修复子 Agent 中 WebSearch 返回空结果；修复 tmux teammate pane 键盘输入泄漏；修复后台任务在 teammate 结束时被误杀

  ([Claude Code Changelog](https://code.claude.com/docs/en/changelog), [Anthropic Engineering - How we built Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode))

- **[重大政策调整：Agent SDK 计费变更在当日宣告暂停 - 2026-06-15]** 这是本周影响面最广的非技术事件。Anthropic 原定于 6 月 15 日将 Claude Agent SDK 及 `claude -p`（headless 模式）使用量从 Pro/Max/Team/Enterprise 订阅池中剥离，改为独立月度 credit 计费（按 API 列表价）。该变更在当日**取消执行**：Anthropic 在 Help Center 和订阅者通知中确认 Agent SDK 使用量继续计入标准订阅限额，不存在独立 credit。

  背景：该变更公告于 5 月 14 日发出，引发社区激烈反弹（重度用户每月可获得相当于 $300–600 API 等价算力的订阅补贴，变更将实质上大幅提价）；外部观察认为 Anthropic 与 OpenAI 的价格战压力是主要原因之一。

  ([The New Stack - Anthropic 暂停 Agent SDK 变更](https://thenewstack.io/anthropic-pauses-claude-agent-sdk-subscription-change/), [The Decoder 报道](https://the-decoder.com/anthropic-backs-off-unpopular-billing-overhaul-as-price-war-with-openai-looms/), [digitalapplied.com 详解](https://www.digitalapplied.com/blog/anthropic-claude-credit-overhaul-june-15-2026))

## 竞品雷达 (Competitor Radar)

- **[Gemini CLI 于 6 月 18 日正式停服 — CI/CD 流水线大规模中断]** 本周四（6 月 18 日），Gemini CLI 如期停止为所有 Google AI Pro/Ultra 订阅者和免费用户提供服务，每条调用 `gemini` 命令的 CI/CD 流水线、定时脚本和 IDE 集成全部失效。迁移目标 Antigravity CLI（Go 重写，闭源）在以下几点引发了大量抱怨：
  - **免费配额悬崖**：Gemini CLI 的免费层约为每日 1,000 次请求；Antigravity CLI 的免费层仅约 **20 次**，降幅 98%
  - **静默失败风险**：MCP 配置字段 `url` 须改为 `serverUrl`，但迁移脚本不自动修复，工具表面加载成功、在实际调用时才报错
  - **迁移脚本不覆盖自动化**：所有直接调用 `gemini` 的脚本、cron 任务、CI 配置均需手动审计，官方脚本不处理这些场景
  - 企业级 Gemini Code Assist Standard/Enterprise 用户豁免，可继续使用 Gemini CLI 和 Antigravity CLI

  ([TechTimes - Gemini CLI 停服当日报道](https://www.techtimes.com/articles/318660/20260618/gemini-cli-shutdown-takes-effect-ci-cd-pipelines-break-go-based-antigravity-cli-arrives.htm), [AI Weekly 分析](https://aiweekly.co/node/3134), [digitalapplied.com 迁移指南](https://www.digitalapplied.com/blog/gemini-cli-to-antigravity-cli-migration-june-18-2026-guide))

## 实用技巧 (Tips & Tricks)

- **`/config key=value` 在线修改设置（Claude Code）**：v2.1.181 起，无需打开配置文件，直接在提示框中输入 `/config theme=dark` 等命令即可实时修改设置，支持交互式、print 模式（`-p`）和 Remote Control 三种场景。用 `/config --help` 查看所有可用 shorthand key。([v2.1.181 Changelog](https://code.claude.com/docs/en/changelog))

- **`Tool(param:value)` 精细化权限规则（Claude Code）**：v2.1.178 新增的权限语法允许按工具输入参数匹配，例如 `"allow": ["Agent(model:opus)"]` 可将自动批准范围精确限定在 opus 模型的 Agent 调用，而不是放开所有 Agent 调用。这对需要精细管控 sub-agent 行为的企业场景非常实用。([v2.1.178 Changelog](https://code.claude.com/docs/en/changelog))

- **`CLAUDE_CLIENT_PRESENCE_FILE` 抑制手机推送通知（Claude Code）**：v2.1.181 引入的新环境变量，适用于无人值守的后台自动化脚本——设置该变量后 Claude Code 不会向移动端发送推送通知，避免深夜定时任务打扰用户。([v2.1.181 Changelog](https://code.claude.com/docs/en/changelog))

- **Auto 模式下的 git 破坏性操作守卫（Claude Code）**：v2.1.183 起，auto 模式会阻断未经请求的 `git reset --hard`、`git clean -fd`、`git stash drop` 等命令；`git commit --amend` 仅在当前 agent 会话创建了该 commit 的前提下才被允许。对于在 auto 模式下大量使用 Claude Code 的用户，这个守卫减少了因"批准疲劳"而误批高风险操作的概率。([v2.1.183 Changelog](https://code.claude.com/docs/en/changelog))

- **Codex CLI `/import` 从 Claude Code 迁移配置（Codex CLI）**：v0.140.0 起，可用 `/import` 选择性导入来自 Claude Code 的 setup、项目配置和近期对话历史。对于同时使用两个工具的开发者，可以将 Claude Code 积累的 CLAUDE.md 和常用配置快速带入 Codex 工作流。([GitHub Release 0.140.0](https://github.com/openai/codex/releases/tag/rust-v0.140.0))

## 横向洞察 (Cross-cutting Insights)

**本周最大的共同主题是"自主性与安全性的边界重新校准"**。Claude Code v2.1.183 引入 auto mode 安全守卫，使其在不打断用户的前提下拦截高风险操作；v2.1.178 的 Agent Teams 架构重组（移除显式创建/删除团队）则在反方向简化了多 Agent 的编排门槛。这两件事并不矛盾——Anthropic 正在用分类器做更细粒度的判断：哪些操作应该自动放行、哪些应该静默阻断、哪些才需要用户确认。这比二元的"要么全允许、要么全问"模型更接近真正的生产级 agentic runtime。Anthropic 工程博客同步披露这一设计背后的"批准疲劳"动机，显示这不只是功能迭代，而是对 auto mode 产品哲学的系统性梳理。

**Anthropic 临时叫停 Agent SDK 计费变更，是本周影响最大的"非技术决策"**。这一戏剧性反转（公告在原定生效当日撤回）说明 Anthropic 对订阅用户的价格敏感度判断出现了低估，也说明开发者社区的集体反弹在短时间内形成了足够的压力。更值得关注的长期含义是：Claude Agent SDK 作为"订阅补贴"的现状本身是不可持续的——无论这次如何，后续的计费边界调整几乎是确定会来的，只是节奏和幅度会更谨慎。企业端应提前为 agent 任务建立成本模型，而不是依赖当前的订阅补贴定价。

**Gemini CLI 的死亡落地，正式开启了一个"开源 AI CLI 工具的信任后果期"**。98% 的免费配额削减、无 1:1 功能对等的闭源替代、破坏 CI/CD 的静默迁移失败——这三个问题同时出现，让 Gemini CLI 的关闭成为一次教科书级的开发者关系危机。而在同一周，Codex CLI 推出 `/import` 专门从 Claude Code 迁入用户，隐含地说明：当开发者曾经一次被工具绑定后吃亏，他们会主动寻找"迁移成本更低"的下一个工具。OpenCode 的持续增长（与两大厂商产品同期保持 star 增速）提示 model-agnostic + 开源治理结构在此背景下具有持久的竞争溢价，而不只是功能差异。
