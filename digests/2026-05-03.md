## Claude Code 产品更新 (Claude Code Updates)

- **[v2.1.126 - 2026-05-01]** 本周最大版本更新。`/model` 选择器现可通过 `ANTHROPIC_BASE_URL` 指向兼容网关时，直接从 `/v1/models` 端点列出可用模型；新增 `claude project purge [path]` 命令，可彻底清除项目所有 Claude Code 状态（会话记录、任务、文件历史、配置项），支持 `--dry-run`、`-y`、`-i`、`--all` 等参数；`--dangerously-skip-permissions` 现可跳过 `.claude/`、`.git/`、`.vscode/` 及 Shell 配置文件的写入确认；`claude auth login` 现支持将 OAuth 授权码直接粘贴到终端，解决 WSL2、SSH 及容器环境中浏览器无法回调 localhost 的问题；OpenTelemetry 新增 `claude_code.skill_activated` 事件（含 `invocation_trigger` 属性），记录用户手动键入斜杠命令的调用行为；Windows 下 PowerShell 7 检测逻辑改进，正式将 PowerShell 作为主 Shell。([GitHub Releases](https://github.com/anthropics/claude-code/releases))

- **[v2.1.123 - 2026-04-29]** 修复在 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` 时 OAuth 认证陷入 401 重试死循环的问题。([GitHub Releases](https://github.com/anthropics/claude-code/releases))

- **[v2.1.122 - 2026-04-28]** 新增 `ANTHROPIC_BEDROCK_SERVICE_TIER` 环境变量，支持选择 AWS Bedrock 服务等级（`default`、`flex`、`priority`），通过 `X-Amzn-Bedrock-Service-Tier` 请求头发送；`/resume` 搜索框现支持粘贴 PR URL 直接定位创建该 PR 的会话（支持 GitHub、GitHub Enterprise、GitLab、Bitbucket）；修复图片尺寸调整逻辑（最大尺寸从误设的 2576px 修正为 2000px）；修复 Bedrock/Vertex AI 输出配置和 token 计数问题，以及多处 MCP OAuth 渲染问题。([GitHub Releases](https://github.com/anthropics/claude-code/releases))

- **[Claude Opus 4.7 集成深化]** Opus 4.7（4 月中旬发布）本周在 Claude Code 中的集成持续落地：支持 `xhigh` 推理努力级别（介于 `high` 与 `max` 之间），可通过 `/effort`、`--effort` 及模型选择器调用；1M token 上下文窗口 + 128k 最大输出；高分辨率图像支持（最高 2576px / 3.75MP）；在 93 项编程基准上较 Opus 4.6 提升 13%；定价不变（$5/M 输入，$25/M 输出）。([Anthropic 官方介绍](https://www.anthropic.com/news/claude-opus-4-7))

## Codex CLI 产品更新 (Codex CLI Updates)

- **[v0.129.0 - 2026-04-29]** 本周最重要的 Codex CLI 版本，功能密集：
  - **`/vim` 模态编辑器**：在 Composer 中引入 Vim 模态编辑，支持 normal/insert/off 三种默认配置，面向 Vim 用户的第一方适配
  - **`/hooks` 浏览器**：全新插件钩子管理界面，支持工作区共享、访问控制、来源筛选、本地共享路径追踪，以及 pre/post-compaction 钩子执行
  - **会话恢复/分叉选择器重设计**：添加原始滚动回看（raw scrollback）模式和工作区感知的 `/diff` 视图，让会话恢复更直观
  - **`/goals` 可发现性**：`/goals` 命令现列出所有活跃和暂停的 goal，暂停状态的 goal 在 `--resume` 时默认保留，除非用户主动选择
  - **主题感知状态栏**：状态栏颜色随终端主题变化，并支持在提示区显示 PR 摘要和分支信息
  ([GitHub Releases](https://github.com/openai/codex/releases), [Codex Changelog](https://developers.openai.com/codex/changelog))

- **[/goal 工作流持续成熟 - 延续自 v0.128.0]** 上月底发布的 v0.128.0 引入了持久化 `/goal` 工作流（可暂停/恢复），本周 v0.129.0 将 `/goals` 提升为一等命令，形成完整的目标驱动编程闭环。`codex update` 自更新命令也于同期上线，消除了手动维护版本的摩擦。([authorityaitools.com](https://authorityaitools.com/blog/openai-codex-cli-0-128-goals-update-april-2026))

## 实用技巧 (Tips & Tricks)

- **CLAUDE.md + AGENTS.md 双文件策略（Claude Code）**：把实际内容写在 `AGENTS.md`（多 Agent 平台可移植），在 `CLAUDE.md` 中用 `@AGENTS.md` 引用，兼顾跨工具兼容性。([CCBP](https://github.com/shanraisshan/claude-code-best-practice))

- **Hook 比 CLAUDE.md 更可靠（Claude Code）**：CLAUDE.md 属于"建议"（约 80% 遵从率），Hook 是"确定"（100% 执行）。必须每次执行的事（格式化、lint、测试）应写成 Hook，而非仅放在 CLAUDE.md。([Claude Code Best Practices](https://code.claude.com/docs/en/best-practices))

- **Codex CLI `/hooks` 浏览器管理钩子（Codex CLI）**：v0.129.0 的 `/hooks` 界面支持可视化管理所有注册的钩子，包括设置工作区范围的共享访问控制，无需手动编辑配置文件，降低多人协作时的钩子冲突风险。([GitHub Releases](https://github.com/openai/codex/releases))

- **用 Gemini CLI 作为 Claude Code 的"子任务执行器"（Claude Code）**：将 Gemini CLI 集成进工作流，用于处理大规模代码库索引、海量文件搜索等 token 密集型任务，节省主会话 token。([ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips))

## 横向洞察 (Cross-cutting Insights)

本周最显著的赛道信号：**"目标驱动"工作流正在成为新标准**。Claude Code 早在 4 月的版本中引入了 `/goal` 的雏形，Codex CLI v0.128.0 本月带来持久化 `/goal`，v0.129.0 进一步将 `/goals` 升为一等命令。两家最大的 CLI Agent 几乎在同一时间窗口完成了从"单次任务"到"可暂停/恢复目标"的范式迁移，意味着 AI 编程 Agent 正在从"对话工具"向"长驻后台任务引擎"演进。

Windsurf 2.0（Cognition 整合 Devin）和 Cursor 3.0（并行 Agents Window）则代表了 IDE 侧的对应趋势：将 cloud agent 嵌入本地编辑环境，形成"本地 + 云端混合编排"的新形态。与 CLI 阵营的"后台会话"思路本质相同，只是入口在 IDE 而非终端。

赛道分化初现：**Claude Code 重视质量与复杂推理**（更适合架构级任务，SWE-bench 87.6%），**Codex CLI 重视速度与并行**（GPT-5.3 加持，240+ tokens/s，更适合明确任务的规模化执行）。头部工程团队的实际做法：两者组合使用而非非此即彼。
