## 社区热点 (Community Highlights)

- **[Pillar Security "沙盒逃逸周"：4 款主流 Agent、8 个漏洞 - 披露于 7/20~23，本周进入主流媒体]** 本周安全议题的绝对主角，BleepingComputer、TheNextWeb、Techzine 等相继跟进报道：
  - 研究者 Eilon Cohen、Dan Lisichkin、Ariel Fogel 公布 8 个沙盒逃逸漏洞，影响 **Cursor、OpenAI Codex CLI、Google Gemini CLI、Antigravity**
  - **攻击范式的转变**：不正面攻击沙盒。Agent 全程守规矩地待在盒子里，只是写下一个文件——这个文件随后被盒子外的可信工具执行、加载或扫描，逃逸就自动发生了
  - **Cursor**：三条独立攻击路径——由 workspace 内容控制的 `.claude` hooks 配置文件（**CVE-2026-48124**，v3.0.0 修复）、被 Python 扩展执行的改造版 virtualenv 解释器、通过 git fsmonitor 元数据绕过路径规则
  - **Codex CLI**：允许命令白名单被绕过——`git show` 看起来是只读操作但并不是（**GHSA-v4xv-rqh3-w9mc**，v0.95.0 修复）
  - **Docker socket 一击三杀**：同一个 Docker socket 漏洞同时命中 Codex、Cursor 和 Gemini CLI——Agent 能触达的特权本地守护进程，本身就是一个无沙盒的代码执行场所
  - **Antigravity**：绕过 macOS Seatbelt 黑名单 + `.vscode` task 配置

  ([BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-codex-gemini-cli-antigravity-hit-by-sandbox-escapes/), [TheNextWeb](https://thenextweb.com/news/ai-coding-agents-sandbox-escapes-pillar), [Techzine](https://www.techzine.eu/news/security/143038/researchers-bypass-sandbox-security-in-cursor-codex-and-gemini-cli/))

## 实用技巧 (Tips & Tricks)

- **给会话命名并置顶（Codex CLI v0.146.0）**：`/new` 和 `/clear` 现在支持为会话命名，重要线程可以 pin 住，侧边对话（side conversations）可以来回切换而不必关闭。同时跑三四个方向的探索时，这比靠时间戳认线程可靠得多。([GitHub Release v0.146.0](https://github.com/openai/codex/releases/tag/rust-v0.146.0))

- **用临时 fork 做"假设探索"（Codex CLI v0.146.0）**：线程 fork 支持临时模式——fork 出来的分支不会出现在线程列表里。适合"我想试试换个架构会怎样"这类不希望污染主线记录的尝试。([GitHub Release v0.146.0](https://github.com/openai/codex/releases/tag/rust-v0.146.0))

- **Codex 里直接装 Claude Code 插件（Codex CLI v0.146.0）**：v0.146.0 新增了 Claude Code 和 Amazon Bedrock 两个插件 marketplace。继上个版本 `/import` 支持迁移 Claude Code 配置之后，现在连插件分发渠道也打通了——双 Agent 工作流的配置成本继续下降。([GitHub Release v0.146.0](https://github.com/openai/codex/releases/tag/rust-v0.146.0))

- **重新审计"沙盒外的可信工具"（来自 Pillar 沙盒逃逸研究）**：本周研究给出的最实用防御思路是——威胁不在沙盒边界上，而在跨越边界的那条数据通路上。逐项检查你的 Agent 能写、而沙盒外进程会自动读取/执行的东西：`.claude` / `.vscode` 配置、virtualenv 解释器、git hooks 与 fsmonitor 元数据，以及**挂载给 Agent 的 Docker socket**（一击三杀的那个）。([BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-codex-gemini-cli-antigravity-hit-by-sandbox-escapes/))

- **MCP 服务器迁移别拖：12 个月弃用窗口已开始计时（MCP 2026-07-28）**：Roots、Sampling、Logging 进入 12 个月弃用窗口，依赖 `Mcp-Session-Id` 的实现需要迁移。好消息是 TypeScript / Python / Go / C# 四个 Tier 1 SDK 已支持新规范（Rust 处于 beta），SDK 内置迁移指引。([MCP Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/))

## 生态动态 (Ecosystem)

- **[MCP 2026-07-28 正式版发布 - 2026-07-28]** 经过自 5/21 起长达十周的 RC 验证窗口，MCP 史上最大规模修订正式取代 2025-11-25 成为当前版本：
  - **无状态核心**：从双向有状态协议转为 request/response 模型；每个请求自带协议版本、客户端身份和 capabilities 元数据，取消握手和 `Mcp-Session-Id`
  - **MRTR（Multi Round-Trip Requests）**：替代过去需要保持长连接流的服务端发起调用
  - **可缓存的 list 响应**：带 TTL 与 scope 提示
  - **头部路由**：`Mcp-Method` 与 `Mcp-Name` 头支持网关层做授权与路由
  - **授权加固**：RFC 9207 issuer 校验；从动态客户端注册（DCR）转向 Client ID Metadata Documents（CIMD）
  - **正式的扩展框架**：Tasks、MCP Apps、Enterprise Managed Authorization 纳入版本化扩展
  - **破坏性变更**：Roots / Sampling / Logging 进入 12 个月弃用窗口
  - **生态规模**：Tier 1 SDK 月下载量接近 5 亿，TypeScript 与 Python 累计下载均超 10 亿

## 横向洞察 (Cross-cutting Insights)

**本周是罕见的"Claude Code 静默周"，而真正的地基变动发生在协议层。** Claude Code 自 7/24 的 v2.1.220 之后整整八天没有发布新版本——这是本刊追踪四个月来的第一次。但把视线从 CLI 版本号上移开就会发现，本周的变化量级其实更大：MCP 2026-07-28 在 7/28 结束十周 RC 验证正式发版，把协议从双向有状态改成了 request/response 无状态模型。这意味着 MCP 服务器第一次可以像普通 HTTP 服务一样部署在 serverless 和 edge 上，也意味着 Roots / Sampling / Logging 三个能力进入 12 个月的死亡倒计时。OpenCode 本周连发六个版本，主线几乎全是 MCP 兼容性抢修（SSE 重连死循环、legacy SDK 客户端兼容、OAuth 流程兼容）——这就是协议换代的下游震荡在客户端侧的真实样子。工具层安静的一周，往往是基础设施层最吵的一周。

**竞争维度从"模型能力"切换到"单位任务成本"。** OpenAI 在 7/30 把 GPT-5.6 Luna 降价 80%（$1/$6 → $0.20/$1.20）、Terra 降 20%，并把 Codex 与 ChatGPT app 的 Auto-review 从 GPT-5.4 升级到 Luna——净效果是自动代码审查成本下降约 10 倍。注意这里的操作顺序：先降价，再把降价后的模型塞进那个跑得最频繁的 Agent 子任务里。这不是模型发布，是**把 Agent 工作流中最高频的环节的边际成本压到接近零**。当 Auto-review 便宜到可以对每个 commit 都跑一遍时，"要不要审查"这个决策本身就消失了。距 GPT-5.6 系列首发仅三周就砍价 80%，也说明前沿实验室的定价权正在被侵蚀——对使用者是好事，对赛道格局则意味着差异化必须从别处找。

**互操作已经越过"能导入配置"，进入"共享分发渠道"阶段——而安全模型没有跟上。** Codex v0.146.0 新增了 Claude Code 和 Amazon Bedrock 两个插件 marketplace：上个版本是 `/import` 把你的 Claude Code 设置搬过来，这个版本是直接把对手的插件商店挂进自己的客户端。竞争对手之间共用分发渠道，这在传统软件业极为罕见，它承认了一个现实——用户不会二选一，工具间的迁移摩擦已经不再是护城河。但本周的另一半故事恰恰是这种开放的代价：Pillar Security 的八个沙盒逃逸漏洞证明，攻击者根本不需要打穿沙盒，只要让 Agent 写一个文件，交给沙盒外的可信工具去执行就行——`.claude` hooks 配置、virtualenv 解释器、git fsmonitor 元数据、挂载进来的 Docker socket，全是现成的通道。同一周 Anthropic 自己也承认一次配置错误让本应断网的测试环境失去隔离。当插件、技能、配置在工具之间自由流动时，信任边界就从"我的沙盒"变成了"所有能读取我产出物的进程的并集"——目前还没有任何一家厂商在这个层面上给出答案。
