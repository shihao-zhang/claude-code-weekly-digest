## Claude Code 产品更新 (Claude Code Updates)

- **[Projects 重做：从「文件夹」变成「一个不结束的对话」- 2026-09-17]** 本周 Claude Code 最重要的产品动作，官方博文标题就叫 *Projects redesigned: from folder to conversation*：
  - **结构是「协调者 + 线程」**：你只和一个**协调者**对话，它负责**界定需求、拆分委派、协调并行线程、review 产出、最后把结果组装起来**
  - **每条线程是一个独立的 Claude Code 云端会话**，跑在**自己的分支和自己那份仓库副本**上。多条线程动到同一段代码时，**冲突以 merge conflict 的形式暴露出来**——这是目前所有并行 Agent 方案里最诚实的一种处理方式：不假装能自动调和，而是退回 git 已有的语义
  - 协调者与线程共享**一份记忆**和**一个公共的文件与 artifact 库**
  - 官方给的例子是「把结算链路 p75 延迟降下来」：让 Claude 逐个 endpoint 做 profile、并行试优化、并行开 PR
  - **放量口径很窄**：9/17 起仅对**一部分 Pro / Max 用户**开放，且需满足「在用云端会话」+「在 web 或桌面端还没有已存在的 project」。之后数周扩到更多 Pro/Max，再到 Team/Enterprise，再进 chat 与 Cowork，**本地执行排在最后**

- **[v2.1.277 - 原生读 AGENTS.md：一个挂了很久的 issue 被关掉了 - 2026-09-18]** 本周传播最广的一条，由 Claude Code 团队的 Thariq Shihipar 宣布：
  - **项目里没有 CLAUDE.md 时，Claude Code 直接读 AGENTS.md**。此前只能从 CLAUDE.md 里 import 或做符号链接，社区为此开的 issue 攒了 **4,300+ 赞 / 5,200+ reactions**
  - **判定规则要记准**：参与「有没有 CLAUDE.md」判断的只有三个文件——工作目录及其上层的 **`CLAUDE.md`、`.claude/CLAUDE.md`、`CLAUDE.local.md`**。而 **`~/.claude/CLAUDE.md`、组织托管的 CLAUDE.md、`.claude/rules/`** 不参与判定，**会与 AGENTS.md 一起加载**
  - 行为可在 `/config` 的 **"Project instructions"** 里切换
  - **一条重要限制**：截至 9/18，这个回退**尚未覆盖 Bedrock / Vertex AI / Foundry**，只在独立 CLI 与桌面端生效
  - 同版其他新增：`CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1`（给「唯一出口是正向代理」的 Claude apps gateway）、gateway upstream 的可选 `headers:` 静态头映射、后台任务在 `/tasks` 等面板开着时完成会提示「更新待查看」
  - 修复里有几条值得注意：**`claude -p` 与 Agent SDK 会话在内部错误后无结果地挂住**、**历史里存在空 text block 时每个请求都报 "text content blocks must be non-empty"**、**同机存在旧版 Claude Code 会把你登出**、Windows 上工作目录路径过长导致 PDF 读页失败
  - VS Code：**agent map 里加入后台 shell 与运行中的任务**、Copy response 按钮与 `/copy`

## 社区热点 (Community Highlights)

- **[AGENTS.md 这件事，社区等的不是功能而是一个态度]** 这是本周讨论量最大的一条，HN 上的标题直接用了 *"Anthropic **finally** adds AGENTS.md support to Claude Code"*：
  - 数据侧：**超过 60,000 个开源项目已采用 AGENTS.md**，支持方包括 **Codex、Cursor、Devin、Gemini CLI、GitHub Copilot、VS Code**，一份 2026 年针对 **2,926 个 GitHub 仓库**的研究指出，**上下文文件已经是开发者给编程 Agent 下指令的最主流方式**
  - 情绪侧：这个请求在 Anthropic 的 issue 列表里挂了很久（**4,300+ 赞 / 5,200+ reactions**），此前官方态度一直偏冷，社区里甚至出现过专门的「为什么 Claude Code 不读 AGENTS.md」的答疑长文。这次 Anthropic **接受了一个由竞争对手起草的格式**，被普遍解读为**互操作性压倒了产品差异化**
  - 冷静的一面：**仍是「回退」而不是「平级」**——有 CLAUDE.md 就不看 AGENTS.md；**Bedrock / Vertex / Foundry 暂未覆盖**。维护两份文件的团队这周还不能直接删掉一份

  ([Hacker News](https://news.ycombinator.com/item?id=49758250), [Cryptobriefing](https://cryptobriefing.com/anthropic-claude-code-agents-md-support/), [RuntimeWire](https://runtimewire.com/article/claude-code-adds-agents-md-support), [HiveTrail：AGENTS.md vs CLAUDE.md](https://hivetrail.com/blog/agents-md-vs-claude-md-cross-tool-standard), [社区答疑长文（含 issue 反应数）](https://gist.github.com/yurukusa/d36197848911f025add142abefcde685))

- **[skill 同步「默认开启」引发的确定性争议]** v2.1.275 的账号级同步被一部分开发者视为**问题而不是便利**，理由值得所有做 Agent 平台的人读一遍：
  - 核心论点是**打破了「一个 Agent 的工具集 == 它被显式分配的 skill 集」这条不变式**：Agent 可能**静默获得从未被分配的 skill / 插件**，工具面被放大且**没有审计痕迹**——这同时是一个**确定性**问题和一个**供应链卫生**问题
  - 实际反应是**关掉它**：多个开发者在 `settings.json` 里把 `syncClaudeAiSkills` 和 `syncClaudeAiPlugins` 双双置为 `false`，让会话**只加载仓库里声明过的那一套**，并把这个选择写进 ADR
  - 这条和上期 `claude plugin eval` 放在一起看会更清楚：**官方在给插件生态造度量工具的同时，也在悄悄扩大插件的默认分发面**

  ([Issue：审计与退出 claude.ai 同步](https://github.com/bradbrok/PinkyBot/issues/1270), [dotfiles PR：关掉同步并钉住 2.1.276](https://github.com/pszypowicz/dotfiles/pull/7), [Issue：按 surface 决定 channel 归属并写进 ADR](https://github.com/Adam-S-Daniel/agentskills/issues/158), [v2.1.275](https://github.com/anthropics/claude-code/releases/tag/v2.1.275))

- **[Projects 的第一波使用反馈：扇出很爽，额度也很快]** Claude Code Projects 放量当周，社区最早冒出来的讨论不是「能不能用」而是**「一次并行会烧掉多少」**——并行线程各自是一个完整的云端会话，**额度消耗速度与线程数直接挂钩**。考虑到 9/14 刚落地的永久 +25%（相对此前实际额度是 -17%，见上期），**这两件事撞在同一周**，对重度用户的体感是叠加的。([WindowsForum 讨论](https://windowsforum.com/news/claude-code-projects-beta-fans-out-tasks-uses-limits-faster.445030/), [上期：配额变更](2026-09-13.md))

## 实用技巧 (Tips & Tricks)

- **跨工具协作的仓库，现在可以只留 AGENTS.md——但要先确认三件事。** 一是**目录里不能有 `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md`**（有任意一个，AGENTS.md 就不读了）；二是 `~/.claude/CLAUDE.md`、组织托管 CLAUDE.md 和 `.claude/rules/` **不影响判定、会照常一起加载**，所以个人偏好放这些地方最安全；三是**跑在 Bedrock / Vertex / Foundry 上的先别删 CLAUDE.md**，那边还没覆盖。（Claude Code，[v2.1.277](https://github.com/anthropics/claude-code/releases/tag/v2.1.277)、[判定规则](https://runtimewire.com/article/claude-code-adds-agents-md-support)）

- **在意「Agent 只能用我给它的工具」的团队，本周就去关掉账号同步。** `syncClaudeAiSkills: false` + `syncClaudeAiPlugins: false`。默认是开的，意味着**你在 claude.ai 网页上随手启用的 skill 会出现在终端会话里**——CI、生产排障这类场景里，这是实打实的不确定性来源。（Claude Code，[v2.1.275](https://github.com/anthropics/claude-code/releases/tag/v2.1.275)）

- **说到一半想补一句的，用 ctrl+enter。** 新的 send-now 键**打断当前回合并把排队的消息一次性发出**，不用再等它跑完一轮再纠正。长任务里这条省下的是整段返工。（Claude Code，[v2.1.275](https://github.com/anthropics/claude-code/releases/tag/v2.1.275)）

- **在 Bedrock / Vertex / Foundry / gateway 上用 auto mode 的，升到 2.1.278 并看一眼 `/status`。** 服务端分类器**不对分类开销计费**，而且 `/status` 新增的 `Auto mode server` 行会直接告诉你跑在哪一侧。**注意这个默认值本周反转过一次**（2.1.273 改本地、2.1.278 改服务端），所以别凭印象判断，看那一行。（Claude Code，[v2.1.278](https://github.com/anthropics/claude-code/releases/tag/v2.1.278)、[v2.1.273](https://github.com/anthropics/claude-code/releases/tag/v2.1.273)）

- **`ANTHROPIC_BASE_URL` 指向代理 / 网关的，跳过 2.1.275。** 那一版**每个请求都报 `400 … Input tag 'advisor_20260301'`**，2.1.276 当天修掉。这已经是连续第二周出现这类故障——**如果你在这条路径上，把「等一版再升」做成常规策略更省事**。（Claude Code，[v2.1.276](https://github.com/anthropics/claude-code/releases/tag/v2.1.276)）

- **长会话卡在 "unexpected tool_use_id" 反复重试的，2.1.274 修了。** 而且**损坏的 transcript 现在会自愈**，不必再删会话重开。同版还修了 **Streamable HTTP 的 MCP 调用无视超时设置、5 分钟就断**，以及**压缩后恢复会话丢失 `/goal`**。（Claude Code，[v2.1.274](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)）

- **大仓库里觉得「每个回合都慢一拍」的，也在 2.1.274。** 根因是**几千个文件上的 language server 诊断**拖住了每个回合。升级即可，不用去调 LSP 配置。（Claude Code，[v2.1.274](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)）

- **`claude agents` 在自动更新后行为突变的，不是你的配置问题。** 2.1.274 之前，自动更新会让它**丢掉 `--model` / `--effort` / `--permission-mode` / `--agent` 等参数**。（Claude Code，[v2.1.274](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)）

- **Codex 用第三方或自建 provider、v0.155.0 起全挂的，升 v0.155.1。** 根因是**新会话默认开了推理摘要，而不支持该字段的 provider 直接拒绝请求**。0.155.1 把新建本地 TUI 会话的默认改为关闭。（Codex CLI，[rust-v0.155.1](https://github.com/openai/codex/releases/tag/rust-v0.155.1)）

- **MCP 服务器权限让你不安的 Mac 用户，开 Touch ID。** v0.155.0 给本地 TUI 会话的 **MCP 请求加了 Touch ID 验证**——比起事后看日志，这是**唯一一条能在工具调用发生的瞬间把人拉回环里**的机制。（Codex CLI，[rust-v0.155.0](https://github.com/openai/codex/releases/tag/rust-v0.155.0)）

- **Codex 的 worktree 会话攒了一堆的，去 agents 看板清。** v0.155.0 的看板现在能**隐藏 / 归档 / 删除任务**、**显示 worktree 归属**，干净的托管 worktree 可以确认删除。上期刚上的 `--worktree` 这周才有了配套的收纳面。（Codex CLI，[rust-v0.155.0](https://github.com/openai/codex/releases/tag/rust-v0.155.0)）

## 生态动态 (Ecosystem)

- **[AGENTS.md 事实上成了跨工具的上下文标准 - 2026-09-18]** 把这条单独放进生态而不只是产品更新，是因为它改变的是**仓库的形态**而非某个工具的能力：**60,000+ 开源项目已采用**，支持面覆盖 Codex、Cursor、Devin、Gemini CLI、GitHub Copilot、VS Code，现在再加上 Claude Code。对维护者而言，这意味着**第一次有了一条让 Agent 行为在竞品之间保持一致的干净路径**——不用再为每个工具各写一份、各自漂移。([Cryptobriefing](https://cryptobriefing.com/anthropic-claude-code-agents-md-support/), [HiveTrail](https://hivetrail.com/blog/agents-md-vs-claude-md-cross-tool-standard), [Top AI Agent Standards 2026](https://blog.agentailor.com/posts/top-ai-agent-standards-2026))

- **[gstack v1.87.4.0（9/16）— 主题是「别给没跑的检查打分」]** 本周 gstack 在做的事很小但很典型：
  - **`/health` 端点现在保留每个检查器完整的退出状态与诊断输出**。此前的 bug 相当有代表性——**失败的检查会显示为成功，因为管道里的中间命令（比如 `tail`）成功了**。现在按完整输出计全部错误，只展示最后 50 行
  - **健康分数开始披露覆盖面**：点名哪些类别检查过、哪些不可用；部分运行会带着覆盖面一起给分；**完全没跑检查的运行直接报 `"N/A — no checks ran"`，而不是编一个分数出来**
  - 路由侧：模型选 skill 时只评估**已安装的 gstack skill**，内置 CLI 工具不进候选目录
  - 这三条合起来是同一个主张：**一个分数必须能说清它建立在什么之上**——在 Agent 大量产出「看起来完成了」的结论的当下，这个主张的适用范围远不止 gstack

## 横向洞察 (Cross-cutting Insights)

**这一周最值得记的一件事是：Anthropic 在七天内做了两次「跟随」，而且跟得毫不掩饰。** 一次是 **Projects**——上期 Cursor 刚把「不写代码的协调者 Agent + 云端常驻 + 并行子 Agent」做成产品形态，本周 Claude Code 的 Projects 重做几乎是同一张架构图：协调者界定需求、拆分委派、协调并行线程、review 并组装，每条线程一个独立云端会话。另一次是 **AGENTS.md**——一个由 OpenAI 起草、被 60,000+ 仓库采用、在 Anthropic 自己的 issue 区挂了 4,300+ 赞的格式，终于被接受。把这两件事放在一起，本周的结论不是「谁抄了谁」，而是**这个赛道的产品形态收敛速度已经快到让「先发」不再构成优势**：Cursor 的 Projects 领先了七天，OpenAI 的上下文文件格式领先了一年多，最终都变成了**所有人都得有的东西**。真正的差异化正在从「有没有这个功能」，退到「这个功能的默认值怎么设、边界在哪、出问题时谁负责」。

**第二条线，本周三家给出的答案恰好落在同一个问题的三个位置上：人还剩多少控制权，以及这控制权以什么形式交付。** Codex 的选择最具体也最物理——**MCP 请求的 Touch ID 验证**：不是日志、不是审批队列，而是**在工具调用发生的那一刻，要求你的手指按在传感器上**。Claude Code 的选择是**结构性的**：Projects 里多条线程改到同一段代码时，**冲突以 merge conflict 的形式暴露**，不假装能自动调和，而是退回 git 已有的语义让人来裁决。而 gstack 给的是**认识论上的**：不再为没跑过的检查编一个分数，直接报 `"N/A — no checks ran"`。三者的共同点是**拒绝用「看起来完成了」替代「确实验证过」**——这是本周整个生态里最一致、也最健康的一个信号。有意思的是反例就在同一周同一个产品里：claude.ai 的 skill 与插件同步**默认开启**，让 Agent 可以**静默获得从未被显式分配的工具且没有审计痕迹**，社区的第一反应就是集体关掉它并写进 ADR。**同一家公司，一边在 Projects 里把冲突老老实实暴露给人，一边在 skill 分发上把默认值设成了「自动扩大」**——这不矛盾，只是说明「保留人的控制权」目前还是逐个功能拍板的，不是一条贯穿产品的原则。

**第三条线是一个更朴素的观察：Claude Code 的发版节奏正在自己制造成本。** 本周 8 个版本里，**一个是次日回滚**（2.1.276 修 2.1.275 打断所有代理 / 网关用户的 400），**一个把四天前刚改的默认值又翻了回去**（auto mode 分类器，2.1.273 改本地、2.1.278 改服务端）。而这已经是**连续第二周出现「新版打断第三方端点 / 网关用户」**——上期是 2.1.265–267 的 HTTP 400 与 2.1.266 的 gateway 环境变量。更耐人寻味的是官方自己也在往回收：**`/code-review` 这版改用精简的内联提示词，不再派生大量 review 子 Agent**，`Pro` 计划的 dynamic workflow 默认尺寸降为 small，Monitor 的 watch 一律加上截止时间。**一边在 Projects 里把并行扇出推到产品层的核心叙事，一边在自家的 review 流程里收敛扇出、在 Pro 计划上调小默认尺寸**——这两个方向同时存在，说明扇出的成本账在内部也还没算平。对使用者，这周最实际的一条建议因此不是任何新功能，而是：**如果你在网关 / 代理 / 第三方端点这条路径上，把「晚一版再升」固化成策略**。本周的账单是两次，上周也是两次。
