- **[Opus 5.5 的四个破坏性变更：旋钮被收掉了 - 2026-09-22]** 这部分是 API 层的变更，但对写 harness、写 skill、写 CLAUDE.md 的人是直接影响，**发错请求直接 400**：
  - **thinking 不能关**：`thinking: {"type":"disabled"}` 与手动预算 `{"type":"enabled","budget_tokens":N}` 均返回 400。**adaptive thinking 常开**，唯一控制手段是 `effort`（`low`/`medium`/`high`/`xhigh`/`max`，**默认 `medium`**，Opus 5 是 `high`）
  - **不支持强制工具调用**：`tool_choice` 的 `any` 与 `tool` 返回 400（连 token counting 端点也一样），改用 `auto` + strict tool use 或 structured outputs，并在提示词里说清什么时候该用哪个工具
  - **不能 prefill**：`messages` 不能以预填的 assistant 轮结尾
  - **采样参数必须留默认**：`temperature` / `top_p` / `top_k` 传任何非默认值都被拒，「改行为请改提示词」
  - 另外：Claude API 与 Google Cloud 上 computer use 必须用 `computer_toolset_20260801`，旧的 `computer_20251124` 被拒；**工具调用之间的叙述文本从 `text` block 改为 progress-update `thinking` block**（默认 `display: "omitted"` 下文本为空，只渲染 `text` 的客户端会在长回合里「看起来卡住」）；新增 `bio` 与 `reasoning_extraction` 两类 refusal 分类（后者**不走服务端 fallback**，直接返回给你）
  - 官方给了自动化迁移路径：`/claude-api migrate this project to claude-opus-5-5`

  ([Opus 5.5 迁移指南](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide), [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5))

  - **续跑一致性**：修复「续跑/恢复的会话把早先消息以**改变过的形式**重新发出」（并行调用、MCP 输入、tool-search 结果三处）、**超大会话恢复后只剩最后几条消息**、重启后续跑发出不同历史**打掉 prompt cache**、在工具调用中途恢复时 Claude 现在能看到「这个调用结果未知」

## 实用技巧 (Tips & Tricks)

本周的技巧几乎全部来自 Anthropic 的 [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5) 指南——它罕见地是一份**写给 harness 作者**而不是写给聊天用户的文档，里面多数条目对任何工具的 agent 循环都成立：

- **effort 要重新标定，不要沿用旧值。** Opus 5.5 默认 `medium`（Opus 5 是 `high`），且**同一档位下它每回合想得更多**，`xhigh` / `max` 尤其明显。沿用旧 effort 的直接后果是回合变长、输出 token 变多。三个配套动作：把 `max_tokens` 开够（agentic 编码场景官方测试里 **128,000 表现最好**，因为**思考 token 也计入 `max_tokens`**，哪怕思考内容不返回给你）；`xhigh`/`max` 只留给已实测有质量收益的工作；**想少想就降 effort，别写提示词**——后者不如前者可靠。注意顶层 `effort` 改动会**打掉 prompt cache**，只想单轮换档请用 per-message effort（beta）

- **无人值守的 agent 会「汇报完就停」。** Opus 5.5 在长任务里会边做边汇报，而**其中一些汇报是以纯文本结束回合的（`stop_reason: "end_turn"`）**，把它当成任务完成的 agent 循环就停在那了。正确做法：把纯文本结束当成**报告而不是完工证明**；用 to-do 工具或文件维护清单；还有未完成项且没说明阻塞原因时，发一条点名未完成项的续跑消息；**同一任务最多自动续跑 2~3 次**就停下来交给人看。另外，模型启动的后台命令或子 Agent 还在跑时，不要判定任务完成——等它结束并把输出作为下一条 user message 喂回去

- **你的客户端可能会「看起来卡住」。** 工具调用之间的叙述文本在 Opus 5.5 上是 **progress-update `thinking` block**，默认 `display: "omitted"` 下**文本为空**。只渲染 `text` block 的界面在长 agentic 回合里会整段静默。设 `display: "updates"`（beta，`thinking-display-updates-2026-08-18` header）拿到每条更新的摘要。进一步：统计**连续多少个工具步没给用户任何可读内容**，超过（比如）5 步就以 **turn-scoped system message**（`clear_at: "next_user_message"`）追加一句「用户有一会儿没收到你的消息了——用几个词说你在做什么，然后继续」。官方测试里这把「长时间静默」的任务占比**砍掉了约一半，且成本无可测变化**

- **多 Agent 编排请喂时间信号。** Opus 5.5 对「已耗时」信息很敏感。在每条返回给模型的消息尾部加一行 `elapsed 340s / 1200s`，它会按预算配速且**通常远早于预算完成**（所以预算要设得比你真正想花的时间高一些）。无法估预算就只给已耗时，再加一句「Time matters here: do not spend time that can be avoided...」。官方评测里两种信号都让小型 agent 团队比单 Agent 更早完成，**给预算的那组质量还与单 Agent 相当**。注意这和降 effort 不是一回事：**降 effort 减少工作量，给预算主要是让更多 Agent 并行**；预算是建议性的，硬超时得自己写

- **聊天类系统提示词里的「think carefully before answering」该删了。** 模型自己决定想多少，`effort` 才是控制手段。官方在一个聊天产品上实测：删掉这类句子后**回复开始得更早，质量无明显下降**。另有一条针对多轮的：Opus 5.5 有时会为了一条简短追问回头重审早先答案，加「Once you have answered something, treat that answer as done...」可以减少后续轮的思考量——但**长分析和 agentic 任务里别加**，那些场景恰恰需要它回头发现前面的错

- **粘贴内容要打标记，这是 Opus 5.5 抗注入的前提条件。** 它对间接 prompt injection 的抵抗力是历代 Opus 最强的，但要拿到「用户粘贴内容里的指令不被执行」这个行为，需要**把每段粘贴内容用带同一个随机 ID 的 `<pasted_content id="...">` 开闭标签包起来**，并在系统提示词里说明规则。标签是纯文本、可被伪造，所以只能当**多层防御里的一层**

- **前端输出别只说「不要 AI 味」。** 泛泛的「avoid a generic AI look」基本只是把一套默认样式换成另一套。有效的做法是**点名要避开的具体模式**：米白/奶油色背景、标题里的斜体强调词、`01/02/03` 编号小标题、等宽字体标签、胶囊形按钮——然后看它换成了什么，再补名单

- **跨 app 工作流要先让它「四处看看」。** Opus 5.5 倾向于快速动手，而自动化任务依赖的信息常常藏在请求没提到的地方（旧邮件线程里的政策、另一个 sheet tab 上的规则、客户记录上的备注）。加一句「Before taking any action, explore broadly with tool calls: ... including ones the task does not explicitly mention」，官方测试里在 `medium` 与 `max` 两档都明显提高了正确完成率，代价是稍多的工具调用。**但因为这句话让它按找到的东西行动，务必把不可信内容挡在被检索的记录之外**

- **换模型时的两条自动化路径**：`/doctor prompt-audit`（Claude Code v2.1.283 内置，审计 CLAUDE.md / skills / agents / commands 的旧模型写法）与 `/claude-api migrate this project to claude-opus-5-5`（改 model ID、破坏性参数、prefill 替换、effort 校准，并产出人工核对清单；会先让你确认改动范围）。审计报告**只采纳 high / medium 置信度的条目，一条一条来**

## 横向洞察 (Cross-cutting Insights)

**9/22 两家在同一个下午换掉默认模型，但换的方向是反的。** Anthropic 往上顶：Opus 5.5 把 Terminal-Bench 4.0 推到 66.4%，同时降价 20%、缓存读降 60%、输出快 30%+，卖点是「长时自治」。OpenAI 往下铺：Sol 与 Luna 把 API 价格永久砍半，与 Astra 一起形成三档，Codex 的限额切换提示直接改推最便宜的 Luna。这不是同一场竞争的两种打法，而是两个不同的赌注——**Anthropic 赌「单位任务成本」会随模型效率下降（同一任务更少 token、`medium` 打平旧的 `high`），OpenAI 赌「单位 token 价格」的下降更能决定使用量**。Opus 5.5 的定价结构其实同时押了两头：$4/$20 只降 20%，但缓存读 $0.20 降了 60%——**便宜的是「重复读同一份上下文」，也就是长会话**。1M 上下文不再需要 beta header，和这条定价一起读才完整。

**真正的结构性变化是 Opus 5.5 收掉的那四个旋钮。** thinking 不能关、不能强制工具调用、不能 prefill、不能调 temperature——这四个恰好是过去两年 harness 作者用来「驯服」模型的主要手段。官方给的替代方案都是**把意图写进提示词**（该用哪个工具就在提示词里说、要结构化输出就用 structured outputs、要少想就降 effort）。这是一次明确的权力转移：**控制点从请求参数移到了模型自己的判断**。代价并没有消失，只是转移给了 harness——本周 Claude Code v2.1.281/282 两版几乎整版都在补长会话续跑、prompt cache、thinking block 的坑（恢复会话重发改变过的历史、超大会话只剩尾部、模型切换丢思考、`redacted_thinking` 报错、MCP 断线打掉缓存），而 progress update 从 `text` 变成 `thinking` block 这一条，会让任何只渲染 `text` 的客户端在长回合里静默——**Anthropic 自己都得在指南里教你怎么补**。`/doctor prompt-audit` 是这轮转移里最有信号价值的产品动作：它承认了「**提示词、skill、CLAUDE.md 也是需要跟着模型版本迁移的资产**」，而不是一次写好就永远有效的配置。

**治理与分发在同一周一起收口，但自主性的边界还没人解决。** 一边是 `availableModelsMatch: "exact"` 和 `deniedModels`——企业现在可以**在显式列出之前阻断任何新模型**，这恰好是对「厂商单方面换默认模型」的制度性反制，而它和 Opus 5.5 换默认发生在同一周并非巧合。另一边是插件目录提交门户：自动安全扫描、审核状态、安装量与发现分析、以及「未来数周 Claude 与 Claude Code 统一发现体验」——第三方扩展正从 GitHub 上的 awesome 列表迁移到有审核有版本有分析的商店，awesome-claude-skills 连续五期增速放缓是同一枚硬币的另一面。两条线都在把「谁能跑什么」变成可管控的。但本周 HN 上那条「Claude Code 替我签了合同，没问我」指向的是第三件事：**模型能力、企业治理、分发审核都在收紧的同时，「agent 在一次授权里能走多远」仍然靠提示词和习惯在约束**。Anthropic 那份无人值守提示词模板的结尾特意写了「This does not override the need for confirmation on risky or destructive actions」——这句话之所以必须写在提示词里，恰恰是因为它还不是一条产品层面的硬约束。
