## Claude Code 产品更新 (Claude Code Updates)

- **[Claude Fable 5 正式发布，v2.1.170 首发集成 - 2026-06-09]** 本周最大事件：Anthropic 正式发布 Claude Fable 5 和 Claude Mythos 5，这是首个向公众开放的 **Mythos 级别**模型。Claude Code v2.1.170 于同日集成支持，用户可在 `/model` 选择器中将其设为默认。

  核心规格：
  - **API model ID**：`claude-fable-5`；上下文窗口 1M token，最大输出 128k token
  - **定价**：$10/M 输入 · $50/M 输出（是 Opus 4.8 价格的 2 倍）
  - **免费引导期**：Pro / Max / Team / Enterprise 用户从 6 月 9 日起至 6 月 22 日免费使用
  - **平台覆盖**：Claude API、Amazon Bedrock、Vertex AI、Microsoft Foundry，均于 6 月 9 日上线
  - **基准测试**：SWE-bench Verified 95.0%、SWE-bench Pro 80.3%（vs Opus 4.8 的 88.6% / 69.2%）——Pro 榜单领先第二名 11 个百分点；FrontierCode Diamond 29.3%（Opus 4.8 为 13.4%）

  **开发者接入需注意的三项 API 变更**：
  1. **拒绝响应**：Fable 5 含内置安全分类器，高风险领域（网络安全、生物、化学、蒸馏等）会主动拒绝请求；API 返回 `stop_reason: "refusal"`（HTTP 200，非错误），响应体携带触发分类器的标识
  2. **Fallback 机制**：新增 `fallbacks` 参数（beta），服务端可自动在 Fable 5 拒绝时切换至其他 Claude 模型重试；客户端可通过 SDK 中间件（TypeScript/Python/Go/Java/C#）实现同等效果；Fallback Credit 机制避免切换时重复计算 prompt-cache 费用
  3. **Adaptive Thinking 固定开启**：Fable 5 不支持 `thinking: {"type": "disabled"}`，原始思维链内容永不返回，`thinking.display` 可设为 `"summarized"`（返回可读摘要）或 `"omitted"`（默认，返回空）

  Claude Mythos 5（API ID：`claude-mythos-5`）与 Fable 5 能力相同，但**不含安全分类器**，通过 Project Glasswing 受限发布（需联系 Anthropic / AWS / Google Cloud 客户团队申请）。

  ([Anthropic 官方公告](https://www.anthropic.com/news/claude-fable-5-mythos-5), [Claude API Docs](https://platform.claude.com/docs/en/about-claude/models/introducing-claude-fable-5-and-claude-mythos-5), [GitHub Issue #67169 · anthropics/claude-code](https://github.com/anthropics/claude-code/issues/67169), [SWE-bench 基准对比](https://www.morphllm.com/claude-benchmarks))

  - **`--safe-mode` / `CLAUDE_CODE_SAFE_MODE`**：以安全模式启动 Claude Code，自动屏蔽所有用户级定制（CLAUDE.md、插件、Skills、Hooks、MCP 服务器），用于隔离排查"是配置问题还是工具本身问题"；托管策略设置仍正常生效

## 实用技巧 (Tips & Tricks)

- **`--safe-mode` 一键排查 Claude Code 配置问题（Claude Code）**：当 Claude Code 出现异常行为时，用 `claude --safe-mode` 启动——所有 CLAUDE.md、Skills、Hooks、MCP 服务器、插件全部临时禁用，可快速确认问题是来自用户配置还是工具本身。企业托管策略仍然生效，不会绕过安全规则。([v2.1.169 Changelog](https://code.claude.com/docs/en/changelog))

- **`/cd <path>` 跨目录不中断会话（Claude Code）**：v2.1.169 新增的 `/cd` 命令允许在保持会话上下文的前提下将工作目录切换至新路径，Claude 同时更新 git 分支感知——对于在 monorepo 内跨子项目工作的场景非常实用，无需退出重启。([v2.1.169 Changelog](https://code.claude.com/docs/en/changelog))

- **Fable 5 fallback 配置建议（Claude API）**：在调用 `claude-fable-5` 时，建议在请求中传入 `fallbacks` 参数（beta 特性），并设置 `fallback_model: "claude-opus-4-8"`；当 Fable 5 触发安全分类器拒绝时，API 服务端将自动在 Opus 4.8 上重试，且 Fallback Credit 机制抵消重复的 prompt-cache 费用。([Claude API Docs - Refusals and Fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback))

- **Codex CLI code 模式内联 Web 搜索（Codex CLI）**：v0.139.0 起，code 模式中可直接调用 Web 搜索，包括在嵌套 JS 工具调用中触发。对于"需要查文档再写代码"的场景（如 SDK 版本变更、API 签名确认），无需额外切换到 ask 模式，直接在 code 模式内完成搜索+编码闭环。([Codex Release Notes](https://releasebot.io/updates/openai/codex))

- **嵌套 Sub-agent 深度管理（Claude Code）**：v2.1.172 起 Sub-agent 最多可嵌套 5 层。实际使用中建议：控制在 2-3 层以内以保持可观测性，第 4-5 层仅用于确定性子任务（如批量文件格式转换）；结合 `claude agents --json` 和 `waitingFor` 字段监控各层阻塞状态。([v2.1.172 Changelog](https://code.claude.com/docs/en/changelog))

## 横向洞察 (Cross-cutting Insights)

**Fable 5 的发布标志着 AI coding agent 赛道从"模型升级"进入"模型分层"时代**。此前，Claude Code 默认以 Opus 4.x 驱动，用户几乎不需要感知"我在用哪个模型"。Fable 5 打破了这个假设：它更强、更贵、且自带安全分类器（意味着部分请求会被拒绝），这迫使开发者和企业运维第一次需要为 coding agent 的**模型选择设计显式策略**——什么任务走 Fable 5？什么任务走 Opus 4.8？触发拒绝时如何 fallback？这套问题本质上是在把"LLM 路由"引入普通的开发工作流，而 Claude Code v2.1.175 的 `enforceAvailableModels` 和 `fallbackModel`（上周 v2.1.166 引入）已经提前为这个问题准备了基础设施。

**本周最耐人寻味的结构性对比：Anthropic 发布 Fable 5 的同一天（6 月 9 日），Codex CLI 发布 v0.139.0，core feature 是让 code 模式能直接调用 Web 搜索**。这两件事的优先级落差耐人寻味——OpenAI 在 code agent 层面的工程迭代依然稳健（几乎每周一个功能版本），但叙事中心已经明显转向 GPT-5.x 和 Codex cloud agent，CLI 工具的定位更像是"进入 Codex 云端生态的入口"（`/app` 移交桌面端正是佐证）。而 Anthropic 则在 CLI 本体上持续密集投入，本周 7 个版本横跨安全模式、嵌套 agent、模型管控、国际化——Claude Code 仍然是 Anthropic 开发者关系战略的主战场，不只是功能分发渠道。

**Gemini CLI 的谢幕即将在周四落地，这不只是一个产品关闭事件，而是整个生态关于"开源 AI 工具可持续性"的一次公开考试**。Linux Foundation 将其案例化，说明这个问题已经超出了单一产品范畴，正在成为开发者选型的系统性信号：一个 AI coding tool 的开源程度、治理结构、商业路径是否对齐，开始影响工程团队的长期押注意愿。OpenCode 的 171K stars（远超 Codex CLI 的 83K）在某种程度上折射了这个信号的传导——当开发者对厂商绑定感到顾虑时，model-agnostic 的开源工具就会获得超出功能价值的溢价。
